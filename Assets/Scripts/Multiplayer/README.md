# Sinbinder: встроенный LAN-тест (ветка feature/server-prototype)

## Что реализовано

Это **отдельный сетевой песочничный режим**, а не готовый сетевой
«Перетягивание каната» или кооператив сюжетного демо.

- Unity запускает сервер **внутри самого игрового процесса**. Не требуется
  .NET 8, установка отдельного Netcode-пакета, создание сцены вручную или
  настройка NetworkManager.
- Два участника подключаются по TCP; у каждого свой идентификатор,
  кнопка готовности и собственный персонаж на тестовой арене.
- Только сервер назначает тик/порядок приказов, принимает Move/Hold,
  проверяет владельца, координаты и ограничения частоты команд,
  рассчитывает перемещение и рассылает позиции обоим игрокам.
- Ограничен размер сообщения, есть таймаут исходящего пакета,
  отключение прекращает матч. Задачи сети не обращаются к Unity API
  вне главного потока.
- Сцена одиночной игры **временно скрывается**, пока активен тест.
  При выходе её корневые объекты возвращаются. Файлы сцены, управление
  Tab/V и сценарный код не переписываются.
- Код не использует Unity Netcode. Это минимальная самостоятельная
  TCP-вертикаль; для релизной игры нужен дальнейший архитектурный выбор.

## Первый запуск в Unity

1. Открой проект **Unity 6000.3.22f1** на ветке `feature/server-prototype`.
2. В редакторе нажми **Play**.
3. В правом верхнем углу нажми **LAN тест** → **Создать LAN**.
4. Запусти второй экземпляр собранной игры, **LAN тест** →
   **Подключиться**, адрес `127.0.0.1` (если на том же ПК) или LAN IP
   компьютера-хоста. Порт `7777`.
5. Оба нажимают **Готов**. Правой кнопкой по полю перемещают *свою*
   капсулу. Обе машины видят положение обеих капсул.
6. Нажми **Выйти из теста**, чтобы вернуться в одиночную игру.

Для двух окон одной сборки после сборки через `Собрать игру.cmd`:
**дважды щёлкни `Test-LAN.cmd` в корне репозитория**. Скрипт
откроет оба окна с автоматическим подключением и готовностью.

Варианты запуска:

```text
Sinbinder.exe -lan-host -lan-auto-ready -port 7777
Sinbinder.exe -lan-connect 192.168.1.20 -lan-auto-ready -port 7777
Sinbinder.exe -batchmode -nographics -server -port 7777
```

Последняя команда запускает **выделенный тестовый Unity-сервер**
без окна: два клиента отдельно подключаются по IP.

Для проверки без UI:

```sh
python Tools/server/unity_smoke_test.py --host 127.0.0.1 --port 7777
```

Этот скрипт подключает два настоящих сокета, проверяет приветствие,
готовность, запрет чужих приказов, серверное расписание, изменение позиции
и остановку при отключении. Нужен запущенный Unity-сервер. Он не
заменяет запуск Unity и не утверждает, что тест уже пройден.

## Безопасность и ограничения

- Сервер слушает **все локальные IPv4-интерфейсы** (`0.0.0.0:7777`);
  используйте только локальную сеть / доверенную VPN.
- TCP, без авторизации, шифрования, NAT traversal, защиты от DDoS и
  сетевого восстановления после разрыва. **Не открывать порт в интернет**.
- Между двумя компьютерами может потребоваться разрешить TCP 7777
  в брандмауэре Windows; это настройка ОС, не кода.
- Оба клиента должны иметь совместимую сборку. У Unity-арены и
  экспериментального `Tools/server` похожий JSON-протокол, но
  последний **не** симулирует позиции, поэтому для полной проверки
  используйте встроенный Unity-хост.
- **Существующие Warrior, AOS, NavMesh, MapLoader, FogOfWar и игровые
  сохранения пока не синхронизируются.** Тестовая арена использует
  простую капсулу, а не боевой префаб.
- Unity-компиляция/тест матча ещё должны быть выполнены в редакторе.
  Все исходники здесь подготовлены без локального запуска Unity.

## Продолжение до настоящего Sinbinder Multiplayer

1. Выделить серверное владение каждой стороной/Греховодом и юнитами.
2. На сервере запускать имеющиеся решения `BehaviourResolver`, AOS,
   боевую систему, NavMesh и события; на клиентах только отображать
   разрешённое состояние. Не пытаться детерминированно просчитывать
   Unity NavMesh на независимых машинах.
3. Сетевые ID выдаёт сервер при спавне. Не использовать
   `Warrior.Id` (локальный Guid.NewGuid).
4. Настоящие приказы из `SelectionManager` превращать в намерения,
   проверять голос, владение и допустимость действия на сервере.
5. Отдельно синхронизировать исходы голосования AOS с объяснениями,
   здоровье, смерть, постройки, ресурсы, туман войны, журнал своего
   Греховода. Не пересылать скрытые данные чужой стороны.
6. Интеграционный тест с двумя Unity-клиентами и выделенным сервером,
   с отключением и переподключением, до переноса в реальную карту.

Ни один `.cs.later` файл не активирован, основное демо не менялось.
