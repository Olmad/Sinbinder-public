# Tools

## check.py — статическая проверка исходников

```
python3 Tools/check.py          # список замечаний
python3 Tools/check.py --quiet  # только итог
```

Не заменяет компилятор. Ловит тот класс ошибок, из-за которых Unity
не собирает проект **вообще** — а значит, не показывает и остальные:

| Что | Пример из этого проекта |
|---|---|
| CS0246: тип из чужого namespace без `using` | `SinType` в `InventoryItem`, `Warrior` в `VoiceGenerator` — 11 файлов |
| CS0246: тип не объявлен нигде | шестнадцать типов, на которые ссылался код |
| CS0101: тип объявлен дважды | два `GreedModule` в одном пространстве имён |
| CS1503: литерал не того типа | `CreateMemory(…, "гнев", …)` вместо `EmotionType` — семь вызовов |
| CS0841: переменная использована выше объявления | десять строк в `CombatDecisionContext` |
| CS1061: LINQ без `using System.Linq` | там же |
| Скобки не сходятся | — |
| Имя файла ≠ имя MonoBehaviour | `GluttonySkills .cs`, `Inventory.cs`, `TitleCeremony.cs` |
| `using UnityEditor` без `#if UNITY_EDITOR` | три редакторных скрипта; ломает сборку плеера |
| Обёртка стоит ниже `using UnityEditor` | `IconGenerator` — обёртка не работала |

Всего этой проверкой в проекте найдено **двадцать три** ошибки
компиляции, каждая из которых в одиночку не давала собрать проект.

### Проверка проверки

```
python3 Tools/check_self.py
```

Восемнадцать ловушек: на каждое правило — крошечный проект во временной
папке, где ошибка сделана нарочно, плюс заведомо чистый проект, на
котором никто не имеет права сработать. Выход не ноль — правило
перестало ловить.

Заведено после того, как за один день трижды подряд соврал прибор,
а не код: заглушка стенда округляла не как Юнити, заглушка предлагала
конструктор, которого в игре нет, а сама проверка не видела ни одного
вызова вида `new Пространство.Тип()`. Разбор — `docs/13-DRIFT.md`.

Правило, переставшее ловить, не падает и не жалуется. Оно молчит,
а отчёт печатает «Чисто» — самое опасное слово в этом проекте.

Сама самопроверка проверена так же: два правила ломались нарочно,
и она назвала оба. Раньше проверка проверялась разовым зондом, который
каждый раз удаляли; теперь ловушки лежат в файле.

Чистый результат означает отсутствие ошибок **известных видов** —
не гарантию сборки. Перегрузки, версии API Unity и `.meta`-файлы
проверяются только редактором.

## unity-check.ps1 / unity-check.sh — сборка без редактора

```
powershell -ExecutionPolicy Bypass -File Tools\unity-check.ps1
./Tools/unity-check.sh                                    # macOS, Linux
```

Находит нужную версию Unity по `ProjectSettings/ProjectVersion.txt`,
запускает её в пакетном режиме (`-batchmode -nographics -quit`),
прогоняет самопроверку движка и печатает из лога ошибки компиляции,
итог проверки и исключения. Редактор открывать не нужно.

Первый запуск долгий: Unity импортирует ассеты. Дальше быстро.

Скрипт принимает путь к проекту, если запускается не изнутри него:

```
powershell -File Tools\unity-check.ps1 -Project "C:\Unity\Sinbinder"
./Tools/unity-check.sh /home/user/Unity/Sinbinder
```

Код выхода: 0 — самопроверка прошла, 1 — нет, 2 — не нашёл Unity
или проект.

## Что проверяет сам движок

`Tests/SelfCheck.cs` — проверка логики, а не синтаксиса:
спектры, перенос старых душ, распад, оболочки, искушения, геометрия
удара в спину, правила голосования и правило «игрок не видит цифр».

Запуск: меню **Sinbinder → Проверить движок** (Ctrl+Shift+T),
либо компонент `SelfCheckRunner` на объекте сцены.
