# 56. Sinbinder: серверы, комнаты, приватный вход, справедливость по задержке

> Статус: поэтапная интеграция. Основной игровой мультиплеер всё ещё
> не завершён и НЕ проверен в настоящей Unity Play Mode. Не сливать
> feature/server-prototype до приёмочного теста Unity и двух ПК.
> Ветку work-table не трогать.

## Что уже есть в feature/server-prototype

1. `LanServerBookmarks`: игрок вручную указывает IP/DNS и порт,
   сохраняет до десяти адресов в локальных Unity PlayerPrefs,
   выбирает сохранённые адреса и может удалять их. **Пароли и токены
   не сохраняются.** Пока это избранные серверы, НЕ глобальный
   каталог публичных серверов.
2. `LanRoomDirectory`: **изолированный серверный компонент**, который
   умеет создавать комнаты с названием, регионом, вместимостью 2–4,
   владельцем, режимом выравнивания задержки, опциональным
   паролем, списком комнат без секретов и серверными правилами
   входа/запуска/удаления. Пароли никогда не сохраняются в открытом
   виде: отдельная 16-байтовая случайная соль + PBKDF2-SHA256 (120k).
   Лимит попыток существует, но **не заменяет** постоянную
   аутентификацию/защиту по IP при переподключении.
   **Этот каталог пока НЕ подключён к TCP и GUI!** Включать
   передачу паролей по имеющемуся незашифрованному протоколу нельзя.
3. `LanLatencyFairness`: измерение RTT посылкой с сервера
   контрольного пакета с номером, ответ клиента с тем же номером,
   время измеряется **только сервером**. Медиана по последним семи
   измерениям уменьшает влияние отдельных скачков, доступен
   отчёт о пинге и джиттере в LAN-панели.
4. Режимы `-mp-ping-balance off|conservative|balanced`:
   - `off`: никаких искусственных задержек (совместимый режим по умолчанию);
   - `conservative`: приблизительное выравнивание задержки ввода
     низкопингового участника, максимум **2 тика / 100 мс**;
   - `balanced`: более сильное выравнивание, максимум
     **3 тика / 150 мс**.
   Применяется только к будущим игровым `gameOrder` через
   `MatchAuthority`, не изменяет синтетические Move/Hold старой
   тестовой арены и одиночный Tab/V.
   Балансировка не активируется, пока для обоих участников не
   получено минимум три корректных измерения.
5. `Test-World-LAN.cmd [off|conservative|balanced]` запускает
   опциональный реальный Unity-хост с выбранной компенсацией
   (по умолчанию conservative) и два диагностических клиента.
   `Test-World-Auto.ps1 -PingBalanceMode Off|Conservative|Balanced`
   принимает тот же параметр в автоматическом приёмочном прогоне.

## Что означает «уравнять пинг»

Сервер принимает пакет после передачи по сети. Если один игрок
имеет RTT 20 мс, другой 200 мс, примерная разница времени доставки
запроса равна половине разницы RTT, то есть ~90 мс.
В режимах компенсации сервер добавляет до 100/150 мс
**к исполнению игровых приказов с более быстрого соединения**,
но не делает откат к недоверенным временным меткам клиента.
Этим можно уменьшить систематическое преимущество, но нельзя
добиться равных ощущений, исправить потери пакетов или устранить
действие высокого пинга. **Компенсация экспериментальна**:
необходимы отдельные измерения при 20/80/150/250 мс и разном
джиттере, а также реальные тесты боевых атак и блокирования.
Намеренно задержанные ответы на серверные пробы могут
манипулировать оценкой RTT; жесткий потолок уменьшает, но не
устраняет этот риск.

Точность FOV, коллизий, рубежей атаки, анимаций и AOS должна
обеспечиваться авторитетной серверной симуляцией, а не обещанием
«сделать одинаковый пинг» у всех участников.

## План безопасного полноценного лобби

### A. Сервис серверов

- Пользовательский список серверов (реализовано).
- Ручное подключение по IP/DNS и порту (есть).
- Обнаружение серверов в LAN по локальному широковещательному запросу,
  только после проверки и с запретом интернета по умолчанию.
- Публичный каталог серверов: отдельный HTTPS directory с данными
  владельца, региона, версии протокола, количества свободных слотов,
  состояния доступности и ограничения частоты запросов.
- Состояния доступности определяет сервер, а не непроверенная заявка
  клиента. Сохранение HTTPS-сертификатов, без включения анонимного
  произвольного TCP из интернета в текущем прототипе.

### B. Комнаты и управление ими

- Подключить `LanRoomDirectory` к **защищённому** интерфейсу/API;
  не пересылать пароль в plaintext TCP.
- Сервер выдаёт комнате криптографически случайный идентификатор.
  Отображаются: название, регион, игроки/максимум, версия игры,
  карта, режим, доступен ли пароль, хозяин, статус, пинг.
- Хозяин выбирает карту, максимум игроков (2–4 после реализации
  3–4 сторон в реальной игре), пароль, приватность, компенсацию
  задержки. Ограничить редактирование при начавшемся матче.
- Присоединение, уход, готовность, смена карты, принудительное удаление
  участника, передача прав хоста, закрытие комнаты.
- Приглашения/одноразовые токены с TTL; не помещать пароли в
  ссылки, логи и публичные метаданные.
- При обрыве сессии права и игровой `LordId` восстанавливаются по
  подтверждённой идентичности, а не только по номеру TCP-слота.
- В будущем поддержка браузера комнат по сети и отдельного
  хостинга без клиента.

### C. Безопасность и отказоустойчивость

- TLS/защищённый транспорт **до** передачи паролей.
- Аутентификация игрока или безопасный одноразовый токен комнаты.
- Лимиты входа по аккаунту, IP и комнате; защитить от DoS
  и сделать проверку паролей вне Unity simulation thread.
- Ограничения на размер сообщений, повторные операции и идентификаторы
  матчей. Не доверять клиентским сторонам, координатам, урону,
  видимости, времени и пингу.
- Защита от читов не должна собирать чувствительные данные с ПК.
- Логирование без паролей, токенов и приватных ключей.
- Надёжное повторное соединение, snapshot + recovery, резервирование
  мест, сохранение матчей, явный ответ на неудачные команды.

### D. Пинг, джиттер, бой

- Показывать RTT, джиттер, потери/задержки пакетов, режим компенсации.
- Калибровать медиану RTT и обнуление после смены подключения.
- Уравнивание задержки только по серверным измерениям и ограниченным
  тикам; не верить локальным временным меткам.
- Введённая дополнительная задержка не должна влиять на частоту
  принятия решений AOS, симуляцию мира или визуальное FPS.
- Для боевого режима: серверный hit validation, окна блока, отказ от
  неограниченного клиентского отката и влияние задержки на тактику.
- Пользовательские настройки: баланс Off/Conservative/Balanced только
  у владельца комнаты/администратора сервера, с понятным предупреждением.
- Позже нужна повторяемая профилировка на нескольких ПК и VPS,
  со статистикой успешных/отклонённых приказов.

## Автоматические проверки

- `LatencyFairnessChecks`: серверные измерения, устойчивость
  медианы к выбросам, трёхзамерная инициализация, ограничение
  100/150 мс и запрет поддельных значений и слишком больших тиков.
- `RoomDirectoryChecks`: приватный список комнат, проверки прав,
  вместимость 2–4, пароли с PBKDF2, ограничение попыток,
  запрет дублей, завершение комнаты владельцем.
- `ServerBookmarksChecks`: избранные адреса, валидация host/port,
  сохранение/удаление, максимум десять, без секретов.
- Общий `UnityLanHarness`: компилирует настоящий C# LAN код с
  тестовыми Unity API, открывает два TCP-клиента.
- **Граница:** зелёный .NET 8 CI не проверяет настоящую компиляцию
  Unity, работу NavMesh, UI, анимаций, выделенный Linux-сервер или
  реальный интернет-хостинг. Они требуют отдельных gate-проверок.
