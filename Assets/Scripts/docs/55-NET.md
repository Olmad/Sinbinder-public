# 55-NET — сеть «Перетягивания» (черновик 28.10, перенести в Assets/Scripts/docs после замеров)

Слово автора 28.10: «хотя бы локальную игру или через код приглашения — чтобы хотя бы протестировать»;
«подумать над онлайном не только для теста… поставить сервер игры на своём ПК».

## Опора

* **Netcode for GameObjects 2.x + Unity Transport** (пакеты `com.unity.netcode.gameobjects`,
  `com.unity.transport`). В манифесте сейчас только `com.unity.multiplayer.center` — пакеты надо
  поставить; первый раз Package Manager тянет их из сети (на флешке — при интернете, потом кэш).
* **Решает сервер.** Игроки шлют намерения, сервер считает, рассылает итог. Один код — два вида:
  хозяин-игрок (listen-host) и выделенный сервер без окна (сборка Dedicated Server; модуль
  win64_server в Unity флешки есть). Запуск сервера: `Sinbinder.exe -server -port 7777 -map "Перекрёсток"`.
* **Жребия нет** — всё по формуле. Хозяин передаёт карту и номер партии (`MapLoader.Match`): жители,
  события, титулованные, стили ИИ выходят одинаковыми без пересылки.

## Что уходит по сети

* **Намерения (клиент → сервер, RPC):** приказ (вид, точка, цель), подарок, взять/положить тело,
  душу в банку, алтарь (гнездо, ложе, рычаг), стройка (место), дверь, событие — выбор 1/2, слово лидеру,
  отправка отряда. Это ровно то, что сейчас вызывает SelectionManager, GearPanel, Favor.Give, MapEvent.
* **Состояние (сервер → клиенты):** воины — NetworkObject + NetworkTransform (на поле до ~80 тел),
  HP, команда, «к кому верен» словом (не числом); склепы — прочность трона и двери (своей стороне),
  постройки, события (род, срок, решено), журнал — строки своему Греховоду.
* **Туман войны — на сервере:** чужое за туманом клиенту не шлётся вовсе (видимость NetworkObject по
  глазам стороны — FogOfWar уже знает, кто чей глаз).

## Что переделать (одиночки → по Греховоду)

Сейчас «игрок» — один на машину, и часть правды лежит в статиках без имени владельца:

| Где | Что | Как надо |
|---|---|---|
| `Core/Satchel.cs` | банки игрока | по Греховоду (словарь lord → сумка) |
| `Gameplay/Remains.cs` | материал на столе, ноша | по Греховоду |
| `Crypt/CryptUpgrades.cs` | голем по рецепту — `Lords.Player` | спрашивать про того, кто поднимает |
| `Gameplay/SoulManager.cs` | общий список душ на поле | душа — у того, кто собрал |
| `Gameplay/Favor.cs`, `Allegiance.cs`, `Hostility.cs`, `MapEvents.cs (Trophies)` | уже по Греховоду | только синхронизировать |
| `Lords.Player` | «чей голос — игрок» | на сервере — у каждого соединения свой |

RivalLord (ИИ) уже живёт по чужому имени — его путь и есть образец для второго человека.

## Шаги

1. Пакеты, NetworkManager на сцене поля, в лобби — «Создать» / «Подключиться по IP». Двое на одной
   карте, тела Греховодов ходят у обоих. (1 день)
2. Воины, склепы, события — сетевые объекты, спавнит сервер; номер партии — от хозяина. (1 день)
3. Намерения RPC вместо прямых вызовов; одиночки → по Греховоду (таблица выше). (1–2 дня)
4. Туман по видимости, журнал — своему. (½ дня)
5. Выделенный сервер: сборка, ключи командной строки, лог в файл. (½ дня)
6. Доступ из интернета: проброс UDP 7777 / Radmin VPN / ZeroTier — без кода; Relay по коду
   приглашения — когда будет проект в Unity Cloud. (½ дня)

Проверка — пакетно: два процесса на одной машине (сервер `-batchmode -server`, клиент `-batchmode
-connect 127.0.0.1`), MatchRun со стороны клиента: приказ ушёл, воин пошёл у обоих, трон пал у обоих.
