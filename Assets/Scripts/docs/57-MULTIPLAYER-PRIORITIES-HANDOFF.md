# Sinbinder — передача разработки мультиплеера между сессиями
**Актуализация:** 11 ноября 2026. **Рабочая ветка:** `feature/server-prototype`. **Черновой PR:** [№1](https://github.com/Olmad/Sinbinder-public/pull/1). **Версия Unity:** 6000.3.22f1.

> **Назначение:** это единый приоритетный backlog и инструкция для следующей сессии разработчика/агента. Документ не утверждает, что весь план выполнен. Другой сессии: начать с проверки текущего SHA и CI, не полагаться на зафиксированный здесь SHA как на актуальный. Параллельно идут коммиты по обучению/AOS; не перезаписывать работы другой сессии.

## 0. Неприкосновенные условия

1. **ЗАПРЕЩЕНО трогать `work-table`:** не читать, не сравнивать, не модифицировать и не переносить код. Не менять `main`, не сливать PR №1 самостоятельно. Писать только в `feature/server-prototype` через маленькие проверяемые коммиты.
2. Исходное сюжетное демо уже играбельно. Сохранять его сцены, AOS и управление: **Tab** — тактический вид/первое лицо; **V** — «Командир/Воин» только в первом лице, камера не меняется; «Командир»: ЛКМ выбор, ПКМ приказ; «Воин»: ЛКМ атака, ПКМ блок.
3. AOS должен оставаться существующим полноценным AOS (13 голосов/модули), а не дублироваться упрощённым сетевым ИИ. Сервер предлагает команду `Warrior.IssueCommand`; успешная доставка **не равна** согласию воина.
4. Не путать **тестовые капсулы**, **локальную `Multiplayer_Test`**, **сетевой канал реального приказа** и **готовую общую игровую карту**. Последняя пока не подтверждена.
5. Не заявлять «проверено в Unity» без логов/артефактов настоящего Unity Editor/Player. Зелёный CI компилирует часть игровых исходников **с заглушками Unity**, а не весь проект.
6. Пароли комнат **не пересылать через нешифрованный TCP**. Не вводить публичный интернет-доступ до TLS/сессионной авторизации/лимитов запросов.
7. Любое изменение: проверить HEAD/CI → изучить зависимости → минимальный патч → регрессионный тест → CI на новом SHA → отчёт с ссылками. При красном CI — исправить/откатить, не наслаивать новую функциональность.
8. Учитывать конкурирующие сессии: проверять blob SHA перед update_file, не править одновременно одни файлы, не делать фиктивных коммитов.

**Уже есть в коде (с разной степенью проверки):**
- `LanRoomServer`, `LanRoomClient`, `LanWire`, `LanMessage`: 2 TCP-клиента, лобби, готовность, тестовые капсулы, heartbeats, остановка и защита очередей.
- `MatchAuthority`, `NetworkActorIdentity`: серверные ID, связь участника с Греховодом, права и защита от повторных приказов.
- `ServerWarriorOrderBridge`, `ServerWorldProbe`: приказы настоящим `Warrior` на авторитетных тиках, учёт нейтральных воинов, интеграция с AOS; опциональный тестовый мир `-mp-world-host`.
- `RivalLord.NetworkControlled`: задел для отключения стратегического ИИ второго Греховода только в сетевом хосте. Требует Play Mode-подтверждения.
- `gameMatch/gameOrder/gameAccepted/gameRejected/gameResolved` по TCP и `worldBegin/worldActor/worldEnd` с приватными ID/ролями/позициями/HP для ограниченного списка воинов. Нет полной визуализации реального мира на клиентах.
- `LanLatencyFairness`: измерение серверного RTT; `Off`, `Conservative` до 100 мс, `Balanced` до 150 мс дополнительного ожидания для более быстрого игрока. Не делает интернет-соединения равными.
- `LanServerBookmarks`: до 10 сохранённых IP/DNS/портов; `LanRoomDirectory`: **изолированная** модель комнат 2–4 места, PBKDF2 + соль, владелец, ограничения попыток. **НЕ** защищённый живой браузер комнат.
- В `Tools/server/UnityLanHarness` тесты сетевых прав, приватных снимков, задержки, комнат, TCP-сценариев; `Tools/server/check_map_assets.py` проверяет GUID/контракты.
- `Test-LAN.cmd`, `Test-Mechanics.cmd`, `Test-World-Probe.cmd`, `Test-World-LAN.cmd`, `Test-World-Auto.cmd/.ps1` существуют. **Наличие сценария не означает, что настоящий Unity Player уже успешно собран и протестирован.**

**Не подтверждено / не завершено:** успешная реальная сборка Unity 6000.3.22f1 и прохождение Test-World-Auto на двух процессах; настоящие 2 игрока в общей игровой 3D-сцене; сетевой бой/анимация/блок/смерть; AOS verdict и память на клиентах; серверный fog-of-war; души/алтари/экономика/события; защищённые живые комнаты, публичный список и dedicated VPS; стресс-тесты.

## 2. Шкала приоритета

- **P0 — обязательный контроль качества:** без выполнения следующую крупную систему не начинать.
- **P1 — сквозной PvP-вертикальный срез:** оба реальных игрока видят и управляют реальным миром.
- **P2 — сердце Sinbinder:** полный AOS и боевые события.
- **P3 — полный игровой цикл:** смерть, души, алтарь, карта, туман.
- **P4 — безопасное расширение:** лобби, VPS, переподключение.
- **P5 — релизная полировка:** производительность, интерфейс, диагностика.

Оценки усилий относительные: S=малая, M=средняя, L=крупная, XL=система из многих PR. Не считать это календарными сроками.

## 4. Что запускать при каждом PR

1. `git status`, актуальный HEAD и workflow runs. Нельзя считать прошедший CI на старом SHA зелёным для нового кода.
2. `Tools/server/UnityLanHarness` и `Tools/server/check_map_assets.py`; при ошибке тестов сначала исправить причину.
3. Настоящие Unity Editor compile, EditMode/PlayMode (если доступно) и `Собрать игру.cmd`.
4. `Test-LAN.cmd`, `Test-Mechanics.cmd`, `Test-World-Probe.cmd`, `Test-World-LAN.cmd`, `Test-World-Auto.cmd` по соответствующим этапам. Запуск только если есть настоящая актуальная Unity-сборка.
5. Сохранить Player.log, WorldHost.log, client logs, SHA и фактически проверенные устройства; различать **статически проверено / C#-TCP тест / Unity локально / 2 ПК LAN / интернет VPS**.
6. Регрессия Tab/V, AOS, алтаря и соло после каждого существенного изменения.
7. В PR указать: задача, что изменилось, тесты, лог, риск, инструкция отката; не сливать до реального Unity-теста.

## 5. Самый полезный следующий реальный шаг

**Не создавать ещё одну крупную подсистему.** Сначала выполнить P0.1 + P0.2 в настоящей Unity 6000.3.22f1:

```bat
Собрать игру.cmd
Test-World-Auto.cmd
```

Или диагностический запуск:
```bat
Test-World-LAN.cmd conservative
```

Если тест не прошёл: взять **точный SHA**, `Logs/Multiplayer`, `WorldHost.log`, оба Client logs, исправить первую подтверждённую ошибку и повторить. Если Unity недоступна текущей сессии, не заявлять запуск, а готовить проверки и изменения, которые можно безопасно статически проверить.

**После успеха:** P1.1 реальная общая карта, P1.3 управление Tab/V двумя Греховодами, затем P2.1 полный AOS и P2.2 бой. Только потом масштабировать комнаты и VPS.

Выполняй **одно наивысшее незавершённое задание** из списка с явным критерием готовности; не переделывай уже существующие возможности, не объявляй проект законченным по C# mock CI и не трогай `work-table`. Если другой агент одновременно пишет код, разделяйте файлы/PR и не конфликтуйте с его коммитами. Публичные комнаты только после защищённого транспорта.
