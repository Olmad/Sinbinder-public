## Разорванные цепочки

### Цепочка приказа — разорвана в трёх местах

Ключевая механика игры. Сейчас код делает противоположное замыслу:
у игрока абсолютная власть, подчинение как решение не существует.

**Разрыв 1.** Приказ не доходит до AOS.
```csharp
// SelectionManager.HandleCommandInput, ПКМ
mover.CommandAttack(enemyUnit.gameObject);   // прямо в NavMeshAgent
mover.CommandMove(hit.point);                // AOS не спрашивают
```

**Разрыв 2.** `HasCommand` никогда не становится `true`.
```csharp
public static DecisionContext Create(Warrior warrior, string commandType = "")
// AOSWarriorWrapper.cs:31
var context = CombatDecisionContext.Create(_warrior);   // второй аргумент не передан
```
Следствие: `LoyaltyModule` всегда возвращает 0, `ObeyCommand` не может
победить ни при каких условиях. Модуль верности — мёртвый код.

**Разрыв 3.** `Execute()` не умеет исполнять `ObeyCommand` — нет ветки
в `switch`, попадает в `default` и ничего не делает.

### Личность одномерна

Все модули греха читают одно поле `soul.SinIntensity`. `SoulData` хранит
один грех и одну интенсивность. Воин с `SinIntensity = 80` предельно жаден,
гневлив и уныл одновременно.

Диздок обещает семь независимых спектров. Кода под это нет. Практическое
следствие: **все воины ведут себя одинаково**, отличаясь только громкостью.

### Действий 62, голосуют 6

Все навыки грехов и классов (56 значений `ActionType`) не попадают в
голосование. `WrathSkills`, `LustSkills`, `SlothSkills` и остальные
написаны и недостижимы.

> **Наполовину устарело — сверено по коду 8 сентября.** Бюллетень
> перестал быть жёстким: `BuildCandidates` опрашивает `ISkillSet`
> и принимает готовые умения. Недостижимы они теперь по двум другим
> причинам: наборы ни на кого не вешаются, и модули (кроме Терпения)
> за свои умения не голосуют. Разбор — `14-HANDOFF.md` §6.

## Решение по Кризисам (28 августа)

Две реализации, ни одна ниоткуда не вызывалась. **Канон — `Core/Crisis/*`.**
Ветка `AOS Engine/CrisisType.cs` (enum + `CrisisManager`, 81 строка) удалена.

Почему так:

| | `AOS Engine/CrisisType.cs` | `Core/Crisis/*` |
|---|---|---|
| Модель | switch с зашитыми числами | `CrisisData` с вариантами выбора |
| Выбор игрока | **симулируется самим кодом** («// Симуляция выбора игрока: заплатить») | первоклассное понятие: текст, исход, цена в золоте |
| Расширение | новый кризис = новый case | новый кризис = новая запись в базе |
| Покрытие enum | 8 значений, тела у двух | 13 значений, все через данные |
| Событие для UI | нет | `OnCrisisTriggered` |

Решает второй пункт. Кризис — это минута, когда решает игрок; реализация,
которая принимает решение за него, отменяет саму механику. Плюс Принцип X:
контент живёт в данных, а не в ветках switch.

**Что при этом выброшено из победившей ветки.** `CrisisResolver` состоял
из пяти бросков `Random.Range`. Это противоречило сразу двум решениям:
поведение рождается голосованием модулей, а не кубиком, и одинаковый вход
обязан давать одинаковый выход (детерминизм заявлен в `07-VERDICT.md`
как сильная сторона). Переписан:

- `WillSaveComrade` — строит контекст «товарищ в беде» и спрашивает
  настоящее голосование: победит ли `SaveAlly`. Ноль новых правил.
- `WillBetray`, `WillBeSeduced` — детерминированный порог по верности,
  морали и невыплатам. Помечены как временные: предательства и подкупа
  нет среди действий голосования. Когда появятся — заменить на вызов
  резолвера, как в первом методе.
- `ResolveDuel` — побеждает сильнейший, ничья решается устойчивым
  сравнением идентификаторов.

**Что стоит перенести из удалённой ветки позже:** пауза игры на время
кризиса, создание воспоминания при оплате, перевод предателя в команду
врага с перерегистрацией в `CombatManager`. Это рабочая обвязка,
её жаль терять — но она нужна вместе с интерфейсом кризиса,
а его пока нет.

### Почему их пришлось завести

Неделю все предметы во всех трёх сценах демо стояли **в сто раз
меньше** и лежали набок — при этом сцены собирались без единой
ошибки, объекты стояли по местам, `check.py`, стенд и самопроверка
молчали. Blender пишет FBX в сантиметрах и с осью Z вверх, Unity
выравнивает это масштабом (×100) и поворотом (270° по X) корня
модели, а сборщики сцен задавали масштаб и поворот напрямую
и затирали выравнивание.

Такую поломку не видит ни одна проверка, которая смотрит на код:
код верен, неверен результат. Поэтому теперь их две новых — та,
что **меряет** (`ModelCheck`), и та, что **смотрит** (`Snapshot`).

Разбор целиком, вместе с оговоркой про вещи на кости —
`14-HANDOFF.md` §49–§55.

### Здоровье: одна правда, у тела

| Что | Где |
|---|---|
| `Warrior.HP`, `MaxHP`, `IsDead` читают тело (`Damageable`), когда оно есть | `Warrior.cs` |
| урон и лечение воина идут в тело; смерть — тем же путём, что в бою | `Warrior.TakeDamage`, `Heal`, `Damageable.Heal` |
| запас тела — **от оболочки** с износом, уровня в нём нет | `ShellData.EffectiveHP`, `Damageable.Awake` |
| первая волна охотников выходит побитой — 40 % запаса | `HunterSquadSpawner._firstWaveHealth`, `Damageable.Wound` |

Почему это важнее, чем выглядит. У воина было две полосы здоровья:
бой бил по телу, а душа читала свою, которую бой не трогал никогда.
Для движка решений убитый оставался жив, а раненый — цел. Страх
«бежать, когда ранен», спасение раненого товарища и лечение умениями
**в настоящем бою не срабатывали ни разу**. Теперь сработают, и бой
от этого изменится: смотреть, не стало ли бегства слишком много
(`14-HANDOFF.md` §58.2). Если стало — это настройка порогов, а не откат.

Запас тела в бою, с износом:

| Оболочка | Запас |
|---|---|
| Призрак | 24 |
| Скелет (отряд, Греховод) | 29.7 |
| Человек (охотники) | 40; первая волна — около 16 |
| Зомби | 43.5 |
| Голем | 79.8 |

**Удар и защита до боя по-прежнему не доходят**: у всех удар 5,
защиты нет. Это та же болезнь, что была со здоровьем, и она открыта —
`11-MISSING.md`, раздел «на 24 сентября».

### Мёртвые не действуют, титулы — только живым

* Павший не говорит (строки павшего в разговоре пропускаются), такт
  решения у него стоит, над трупом отказ не повторяется.
* Мёртвый Греховод не ходит с клавиш, не жнёт, не трогает суму.
* `TitleManager.UpdateTitle` не присуждает ничего павшему и Греховоду.
  Вход в титулы один на все семь путей — закрыто на нём. Церемония,
  дождавшаяся очереди, у погибшего отменяется.
* **«Тень»** — за два боя без единого удара (`DeedType.StayedOut`,
  пишется в конце боя тому, кто выжил и не ударил; признак «ударил»
  ставит `Damageable.TakeDamage`). Прежде она давалась за одно выживание,
  то есть всему отряду после первой волны.

### Смерть Греховода — конец игры

`SinbinderPlayer` замечает свою смерть и показывает экран «Греховод пал»
(`GameOverUI`, собирается кодом в любой сцене). Мир стоит паузой,
которую чужой `Resume` не снимает (`GamePauseController.Halt`). Кнопки
две: «Начать сначала» — лагерь, и стартовый вопрос задаётся заново
(`StartPanel.Forget`); «Выйти из игры». В игре с обязательством запись
стирается (`SaveSystem.EraseBound`): переиграть смерть нельзя.

Тот же экран — «Отряд не вернулся», если отряд лёг там, где экрана
конца демо нет (он стоит только в склепе). Прежде игрок оставался
на пустом поле без кнопок.

На экране конца F5, F6 и окно записей (F9) не пишут и не грузят
и говорят почему: запись после смерти воскресила бы пропащий забег.

### Сюжет не идёт по таймерам

Шаг игрока ждёт игрока — `Beat.UntilPlayer`. Срок не делает шаг
за него, а раз в минуту (у шара — раз в сорок секунд игры) журнал
напоминает, чего ждут:

| Шаг | Напоминание |
|---|---|
| отойти от палатки | нет — ждёт молча |
| подойти к столу с шаром | «Карган ждёт у стола с шаром.» |
| разобрать сундук Марги | «Карган ждёт у сундука Марги.» |
| вернуться к горящему шару | «Карган: «Владыка, шар. Скорее».» |
| войти в зал склепа, к алтарю | «Зал впереди. Алтарь ждёт.» |

Эпилог — через четырнадцать секунд **после** того, как Греховод дошёл
до алтаря (3.5 м по земле). Сроки со страховкой остались только там,
где игрок ничего исправить не может: заставка, провожатый, сцена без
шара, вторая волна при несобранных душах, край карты, который никто
не открыл. Истекая, они пишут в консоль `[ПРОЛОГ] …`.

### Разгром — событие лагеря

Шар договорил — ведущий лагеря разворачивает разгром на месте
(`RaidEvent.Stage`), без загрузки: строка «Лагерь знали не только
свои.», отъезд камеры, рог, две волны охотников (трое, затем шестеро),
край карты на востоке, за палатками. Греховод и отряд остаются там,
где стояли. Побег ведёт в склеп, как прежде.

Попутно: ушедшие по решению совета теперь удаляются со сцены, а не
выключаются — рамка больше не выделяет невидимых, и гибель отряда
засчитывается. Смена доли переносит пол, ремесло, братство и славу
(`SquadRoster.Remember`): уникальная женщина больше не входит в склеп
мужчиной.

### Враги гонятся, охотники знают, куда идти

* **Погоня.** Враг в поле зрения (30 м, `CombatDecisionContext.SightRadius`)
  делает «атаковать» кандидатом; гнаться ли — решает голос. «Бежать» —
  только от тех, кто в десяти метрах. Цель удара ищется в тех же 30 м.
* **Свои и чужие — с точки зрения спросившего** (`CombatManager.GetAllies`).
  До этого охотники считали своими наш отряд, а врагами — товарищей.
* **Цель охотника** (`HunterGoal`) — куда идти, когда в десяти метрах
  драться не с кем, а голос выбрал стоять, грабить или бить далёкого.
  Первая волна — к костру; дошла (4 м) — дальше голос. Вторая — по следу
  (`SinbinderTrail`): туда, где Греховода нашли в последний раз.
* **Инквизитор второй волны** (`Scryer`; один из шести — виды идут
  по кругу: охотник, следопыт, Инквизитор, ловчий) раз в 7 секунд игры
  находит Греховода. Вспыхивает свет над обоими (0.9 с, `FlareSeconds`;
  в `14-HANDOFF.md` §66.3 записано «полторы секунды» — код говорит 0.9).
  Журнал один раз: «Инквизитор шепчет над ладонью — охотники повернули
  к Греховоду.» Жив — след свежий, стая ждёт на месте нового заклинания;
  убит — «Инквизитор пал — охотники потеряли след», стая доходит
  до последнего места.
* Вспышка видна и сквозь туман, где самого Инквизитора не видно, —
  нарочно, слово автора (§69). Решить после прогона.

### Туман войны — как в Warcraft 3

* **Знание** — `FogOfWar`: сетка по полметра на всю землю, пересчёт
  раз в 0.1 с. Зрение воина 12 м, Греховода 14. Не разведано — чёрное;
  разведано и не видно — серое; видно — как есть. Край зрения плавный
  (0.3 с).
* **Картинка** — `FogOfWarFeature`, проход рендера по всему кадру
  (Render Graph, URP 17.3) с шейдером `Hidden/Sinbinder/FogOfWar`
  (`Assets/Shaders/FogOfWar.shader`), подключён в `PC_Renderer`
  и `Mobile_Renderer`. Идёт до прозрачного: круги выделения и полоски
  над головами им не гасятся. Только игровая камера.
* **Враг вне зрения спрятан целиком**: тело, полоска, коллайдер, свет.
  Его не выделить, не навести подсказку, не приказать бить; выделенный
  теряет выделение. Слово над головой и наезд камеры на него
  не срабатывают. Павший остаётся таким, каким его видели.
* Край карты открывается серым: дорога к нему обязана быть видна.

Проход рендера и шейдер — самое рискованное в дне: сверены
с исходниками URP 17.3, но не собраны. Если упадёт сборка — почти
наверняка там (признаки — `14-HANDOFF.md` §67.3).

### Мышь, выделение, приказы

* **У воинов снова есть тела для луча.** `WarriorRig.Attach` вешает
  капсулу (высота 1.8, радиус 0.45), если коллайдера нет: модели тел
  с 12 сентября импортируются без коллайдеров, и двенадцать дней щелчок
  не выбирал никого, ПКМ по охотнику становился «иди туда», а подсказка
  при наведении молчала.
* **Круги выделения** (`SelectionComponent`): кольцо у ног, строится
  при первом выделении. Свой — зелёный, чужой — красный; цвет берётся
  в миг выделения, так что перебежчик получит цвет нынешней стороны.
* **Рамка** берёт только своих живых. Греховод в рамку с отрядом
  не попадает; обведённый один — выделяется.
* **Щелчок** выделяет любого живого: своего, Греховода — и врага,
  чтобы посмотреть его строку в панели. Щелчок по павшему — промах.
* **Приказы** (ПКМ, Shift + ПКМ, H, G, Esc) уходят только своим живым.
  Врагами управлять нельзя. «Бить» — только живого чужого под курсором;
  врага в тумане луч не находит.
* **Греховод слушается всегда.** Выделенный, он идёт по ПКМ и идёт
  на врага по ПКМ по врагу — ногами, без голосования (`UnitMover`).
* Панель различает «Никто не выделен» и «выделен Греховод».
* Наезд на своеволие («Сбегает») останавливает мир на время кадра;
  пауза знает, кто её ставил (`GamePauseController.Stamp`), и наезд
  не снимает чужую.

### Сохранение

Загрузка возвращает туда, где записался (`SaveSystem.ReturnTo`: сперва
состояние, потом сцена), на всех четырёх путях — F6, меню паузы,
стартовый экран, окно записей. Лагерь, пришедший загрузкой, отряд
не стирает (`SaveSystem.Arriving`, живёт одну смену сцены).
