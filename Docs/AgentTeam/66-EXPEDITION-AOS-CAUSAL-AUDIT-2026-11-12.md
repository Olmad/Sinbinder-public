# Sinbinder — аудит причинности экспедиций и AOS

Дата: 12.11.2026. Рабочая ветка: `feature/server-prototype`. **Это аудит исходников и автоматических CI-контрактов, а не Unity PlayMode.**

## Неподвижные правила

- Самостоятельный выбор воина идёт через существующую AOS с 13 модулями. Ключи личности, тип души, старший, предложение игрока, страх и отношение не подменяются сценарным «правильным решением». Для мирных задач участвуют только модули `IMissionModule`, это *не утверждение*, что в любой миссии активно голосуют все 13.
- Причинная цепочка: *контекст → выбор AOS → попытка исполнить действие → реальное изменение мира → память и отношения → честное объяснение*. Нельзя записывать намерение как успешное действие.
- Командир выбирает развилку самостоятельно, предложение игрока не гарантирует подчинения. Отзыв до столкновения не создаёт боя.
- Автоматические отряды сейчас не собирают души и уникальные секреты. У игрока-Греховода при личном участии есть особые права на сбор; физические тела/оболочки не равны душам.
- Существующий одиночный Tab/V, обе личные карты, арена, сетевой код, пролог и правила смерти не переписываются ради теста.

## Исправлено непосредственно в исходниках в этом проходе

| ID | Нарушенная причинность | Изменение |
| --- | --- | --- |
| C01 | «Отряд возвращается», хотя бой ещё не произошёл | `ResolveEncounter` вызывается **по прибытии** после AOS-развилки; `EncounterResolved`, `Survivors`, `BattleWon`, полный протокол боя и взятые монеты сохраняются до возвращения |
| C02 | Повторный расчёт после F5/F9 может изменить смерть и добычу | Реальный исход сериализуется в `SavedAutoExpedition`; возвращение использует сохранённый результат, а не повторный `Expedition.Fight` |
| C03 | Выживший воин якобы привозит защищённый груз даже при ничьей | `ExpeditionObjectiveRules.Secured` использует AOS `BattleRecord.Winner` и число выживших; не выполненная цель не даёт груз, монеты, секрет или пластинку |
| C04 | Число убитых ошибочно равно числу остановленных врагов | Победа берётся из AOS вердикта: подкупленный противник может выйти из вражеской команды, не умерев |
| C05 | Один персонаж числится и в походе, и в склепе | Отправленный `Warrior` деактивируется как сценовый объект, `SquadRoster` оставляет запись `IsAway`; при возвращении `Settle` восстанавливает выживших |
| C06 | Автобой создаёт упрощённую копию без экипировки/кошелька | И развилка, и бой создают бойца через `Expedition.Summon` |
| C07 | Подкуп переводит врага в союзники и ломает соответствие `squad[i] ↔ away[i]` | Результат считает исходный состав через `originalSquad`; временный общий `SquadGold` сбрасывается на период боя и восстанавливается без утечки |
| C08 | Выбор AOS «бежать» не выводит персонажа из боя | `AutoBattleResolver.Execute` удаляет его из списка участников; следующий ход проверяет действительную принадлежность списку, чтобы подкупленный не действовал за старую сторону |
| C09 | Журнал утверждает спасение/побег/подкуп/лут, даже если не было эффекта | `BattleEvent.Resolved` различает результат и намерение; `Retelling` явно говорит об отсутствии эффекта; `Loot` без предмета не выдаётся за полученную добычу |
| C10 | Тексты обещали собранные души, пленников, оболочки без объектов | `JunctionCatalog` и `MissionBoard` перестали объявлять отсутствующую доставку; нереализованный учёт предметов назван явно |
| C11 | Охрана и возчики для варианта «забрать товар, людей отпустить» требуют кровавого боя вопреки утверждённой бескровной развилке | `TakeGoodsSparePeople` обрабатывается как бескровное разрешение; `TakeEverything` и `TakePeople` требуют боевого расчёта |

## Что НЕ исправлено и не должно считаться готовым

| Приоритет | Разрыв | Точная причина / требуемый следующий шаг |
| --- | --- | --- |
| P0 для полной AOS | **Нет постоянной памяти экспедиций у души.** | `MissionBoard.Decide` передаёт пустой `MissionContext.RecentMemories`. `MemoryProcessor` использует временный `Warrior.Id` симулированного объекта, `Aftermath` меняет только лояльность. Необходимо стабильное хранилище памяти души, перенос между сценами/сохранениями и вход в `DecideMission`; нельзя заполнять фальшивыми воспоминаниями |
| P1 | Полный пространственный реплей | `BattleRecord` фиксирует действия без треков позиций/времени. Доступна честная **схематическая** хронология, не 3D запись маршрута |
| P1 | Полная причинность отступления/добычи на 3D карте | Автобой остаётся счётом без навигации. `Loot` в бою расходует ход на поиски, не выдаёт предмет; действия вне боя требуют реальной логики выбора/переноса объекта |
| P1 | Пленные, оболочки, редкая добыча | Полная инвентаризация, вместимость, тела, их расположение и возврат в склеп не связаны сквозным предметным учётом. Ложная текстовая награда убрана, **система не реализована** |
| P1 | Путь и бой по кадрам | 15+15 секунд — стадии, а событие AOS разрешается одним синхронным расчётом в момент прибытия. Нет регулярных решений во время столкновения и вмешательства по рации |
| P1 | Реальная Unity Editor/PlayMode компиляция, контракты NavMesh и сцен | GitHub Actions .NET и Python source checks не доказывают Unity 6000.3.22f1 PlayMode. Зелёный CI не является приёмкой двух карт |
| P2 | Связь слухов и повторных конвоев с ценностью миссии | `MissionCatalog` выдаёт постоянную таблицу. Утверждённая концепция «второй обоз беднее первого» ещё не моделируется. Не менять доход без отдельного баланса |
| P2 | Авторитет многопользовательского мира | Автосимуляция работает в однопользовательском `MissionBoard`, не как серверная единая история 2–4 Lord. Потребуется отдельная интеграция, не подмена сервера на клиенте |

## Тест-пары, которые должны стать обязательной приёмкой Unity

1. Один воин жив, охрана ещё дерётся → **ничья/отступление, без груза**; тот же бой с фактической победой → **законная добыча**.
2. Греховод сказал «отпустить» → AOS командир вправе ослушаться; в реплее записывается **фактически выбранное**, не предложенное.
3. `Flee` до чужой атаки → воин выходит из списка целей и не наносит ударов позже; `Loot` без предмета → нет монет/предмета в кармане от одного выбора.
4. Подкуп на ходе противника → он не делает следующий ход за старую команду; исходные участники отряда не путаются с новообращённым.
5. Сохранить **после встречи, до возврата** → загрузить: `BattleWon`, выжившие, принятый выбор и подробный протокол неизменны; второй бой не запускается.
6. Два параллельных отряда → не делят кошель подкупа, имена, совет, добычу; отзыв одного не снимает занятость остальных.
7. Автоматический поход к часовне после смерти врага → ни одна душа не появляется на полке; личный поход Греховода → проверяется отдельное физическое собирание.
8. Проверить отрицательное воспоминание после резни/милости и изменённое решение AOS при следующей поездке: **сейчас этот тест должен выявить отсутствие полноценной памяти**, а не быть подогнан под зелёный результат.

## Вердикт

**Причинная последовательность и честность нескольких эффектов улучшены в исходниках.** Полный мир/AOS-контракт **ещё не выполнен**, прежде всего из-за отсутствия долговременной персональной памяти, сквозной предметной экономики и пространственно-временной симуляции. До Unity-проверки PR оставить черновым; в `main` не сливать.
