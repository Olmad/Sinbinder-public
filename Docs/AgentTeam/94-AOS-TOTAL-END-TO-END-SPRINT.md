# 94 — ТИТАНИЧЕСКИЙ СПРИНТ: сквозная проверка AOS (25.11.2026)

Решение автора: максимально полная проверка AOS. Это приоритетный спринт всей команды, не очередной обзор кода. Временно отложить расширение механик (включая Memory Director), кроме исправлений, необходимых для проверяемой работы существующих утверждённых систем. Не менять канон, 13 голосов, правила управления и замороженные границы AOS без решения автора. Не считать отсутствующий задуманный функционал автоматически разрешением реализовать его; отличать дефект, неподдержанную задумку, намеренное ограничение и спорный дизайн. Не трогать work-table. Работать от актуального канонического SHA, не перетирать параллельные патчи; перед изменением сверить ветки и текущие задачи. Спринт заканчивается доказательствами, а не датой.

## 1. Масштаб и обнаружение пропусков

Инвентаризировать весь достижимый и недостижимый функционал из C#, enum, ScriptableObject, prefab, сцен, Resources, JSON, конфигураций, сохранений, локализации, документации, тестов и CI; найти мёртвый код, неиспользуемые поля, потерянные сериализованные ссылки, условные ветки, значения по умолчанию, исключения и несовпадения описаний. Не ограничивать аудит папкой AOS Engine. Для каждого элемента — стабильный ID, источник, ожидаемое поведение, владелец, связи, тесты, дефекты, SHA и уровень доказательства. Генерировать машинную опись, проверять её полноту на каждом изменении. Не использовать прежний PASS как доказательство нового SHA без анализа затронутых зависимостей.

Обязательные домены: семь спектров в обоих полюсах и нейтральности; все 13 голосов и каждый вклад, кандидаты/доступность/победитель/ничья/отказ/колебание, конфиги и весовые пределы; все ActionType, исполнитель и фактический адресат; все перки/условия/эффекты/описания и происхождения, мораль, верность, эмоции, страх, искушения, способности, оружие/экипировка, классы, тактика и приказы; все типы памяти, адресные причины, свидетели, отношения, родство, предубеждения, титулы, слухи и репутация; личные цели, события лагеря и миссии; личные и автономные экспедиции, мир и время, добыча, потери, реальный реплей; Суд полный/короткий/ручной, локализация RU/EN, отказ и контрфакты; обучение, TestChamber, сохранения, переходы сцен, новая игра, производительность и долговременная стабильность. Проверять и врагов, нейтралов, отсутствие командира, смену стороны, мёртвые/отсутствующие сущности. Сеть только в части влияния на одиночную AOS; не расширять сетевую дорожку.

## 2. Обязательная цепочка доказательств для каждой строки

Спецификация → реальный ассет → сериализация/загрузка → создание/достижимость сущности → истинный контекст и ID → доступность кандидата → точные вклады всех источников → победитель/причина и сохранённый бюллетень → фактический исполнитель/цель → изменение мира/памяти/инвентаря → объяснение RU/EN/Суд/реплей → сохранение/загрузка/переход → сравнение личного и авто режима (либо обоснованное отличие) → Unity.
Для каждой применимой ступени отдельный статус, ссылка на доказательство и SHA. N/A только с проверяемым обоснованием и независимым QA. Минимум положительный, отрицательный, граничный и регрессионный тест на каждый эффект/условие; для контекстов также отсутствие цели, другой ID, повтор, смерть/смена стороны/сцены/загрузка. Контрфактический A/B: при неизменном остальном изменение единственной причины должно менять вклад предсказуемо; тестировать вклад отдельно от победителя (не каждый вклад обязан менять победителя). Для недействующего эффекта тест должен краснеть до исправления, зеленеть после, и краснеть при его отключении/мутации. Не заменять реальные данные объектом, искусственно созданным в тесте, в проверке сериализации. Не путать статистическую вероятность с обязательным поведением. Проверять комбинации: попарно для всех применимых измерений, целевые тройки и более для высокорисковых взаимодействий, многосидовые и долгие симуляции; не обещать исчерпывающий перебор бесконечного состояния. Сохранить сиды, входы, фактические результаты, минимальный воспроизводимый пример. Проверять реальное исполнение, не только ActionType. Баланс — отдельная оценка с распределениями, а не произвольные изменения ради PASS.

## 3. Команда и порядок работы

1. Инженер AOS №1: инвентаризация голосов/кандидатов/перков, первая очередь — сохранённая база перков и адресность условий; тесты реальных эффектов, полный след вкладов, без новых голосов.
2. Инженер экспедиций №2: соответствие личного и авто контекста, исполнитель, мир/добыча/реплей/память, изоляция и сохранение; не считать автоэкспедицию доказательством 3D.
3. Инженер UX и текстов №3: Суд, объяснения, все обещания описаний, RU/EN, обучение/подсказки; сопоставлять текст с фактами и не прятать дефекты переписыванием без согласования.
4. Главный инженер №4: сводная опись, тестовая инфраструктура, ассеты/генерация/сериализация/CI, сохранения, интеграция патчей и анализ регрессий; назначать непересекающиеся файлы и проверять актуальный SHA.
5. QA №5: независимое построение описи из исходников и данных, поиск пропусков и ложных PASS, независимый воспроизводящий тест, проверка мутациями и выборочной проверкой исправлений; не принимать собственный патч. Если дефект требует правки, передать владельцу или выделить отдельный патч с другим проверяющим.

Каждый запуск: прочитать план и этот документ; проверить актуальные коммиты/CI/соседние ветки, выбрать незакрытый срез, воспроизвести, добавить тест и минимальную безопасную правку, если полномочия/среда позволяют, доставить коммит/PR; иначе конкретный блокер, воспроизводимый тест и следующий шаг. Никаких отчётов вместо доступных исправлений. Не переписывать чужой файл без сверки. Использовать независимые записи по ID и владельцам, один интегратор сводит матрицу. Не прекращать работу из-за недоступности Unity: делать статические, чистые, source-linked и shim проверки, но не выдавать их за Unity. Не обходить блокер заглушкой. Не менять расписание команды данным документом; инструкции автоматизаций должны ссылаться на него.

## 4. Начальная очередь дефектов (не закрыта)

AOS-T-001 P0: PerkEffect.UnlockedAction объявлен ActionType?; Resources/PerkDatabase.asset содержит 100 PerkName, 113 Condition, 52 ненулевых ScoreModifier, 0 полей UnlockedAction. PerkResolver требует HasValue. Сильное статическое доказательство потери поля; загрузить реальный ассет в Unity и воспроизвести; сериализуемое представление с явным флагом/enum, миграция/регенерация данных без изменения смысла, тест каждого эффекта. Не просто включить все ранее неактивные большие веса: проверить их баланс и Суд.
AOS-T-002 P0: 35 типов условий и 10 отсутствующих в PerkResolver: AristocratMode, BanditMode, WinDuel, AllyIsStudent, InGarrison, LongBattle, NightTime, EnemyIsSnake, RoyalCommander, TargetFound. Затронуты 9 особенностей. Классифицировать как отсутствующая семантика/дефект/неутверждённое расширение, не подставлять приблизительный контекст. В docs/12-BALANCE описано ещё 01.09; предупреждение не исправление.
AOS-T-003 P0: NearChild проверяет любого раненого союзника; EnemyStronger проверяет наличие любого врага; BrotherNearby проверяет совпадение имени перка, не конкретную родственную связь. Сверить TargetWarrior/RescueTargetId и ID нужного лица; отрицательные тесты с чужим раненым, слабым врагом, неродственным обладателем перка.
AOS-T-004 P0: PerkResolver.ApplyPerks после записи голосов; проверить полный баланс вкладов и объяснение победителя; не добавлять новый голос вместо прозрачного учёта модификатора; проверить TemptationResolver и SquadOrders аналогично.

AOS-T-007 P1: RumourManager существует, но намеренно не подключён к голосованию согласно комментарию; проверить действующих писателей/читателей, сохранение/изоляцию, подмену текста при накоплении разных деяний и границы замысла; не подключать новый мотив без решения автора.
AOS-T-008 P0: проверка самих тестов: реальный ассет, отрицательный контроль, тестируемость всех enum/эффектов, сборка против реальных источников, отсутствие ложного зелёного при отключении механизма. Инвентаризировать Tools/aos, Tools/expeditions, Unity tests и workflows; найти мёртвые проверки и статические проверки, которые подменяют runtime.

## 5. Реестр и ворота

Статусы по строке: NOT_INVENTORIED, INVENTORIED, FAIL, BLOCKED, STATIC_ONLY, SHIM_PASS, UNITY_PASS, INDEPENDENT_PASS, ACCEPTED, N/A (основание). Уровни не взаимозаменяемы; FAIL/BLOCKED/непроверенные строки видны отдельно. Записывать версии ассетов, точный SHA, команду/CI URL, ожидаемое и фактическое, идентификаторы входов и исполнителя, владельца, проверяющего и дату. Положительный тест без отрицательного контроля не закрывает строку. Сводка: охват описи, доказательства по уровням, незакрытые дефекты по P0–P2, покрытие каждого домена и конкретные пробелы; знаменатель — фактический инвентарь, не количество созданных тестов. Не использовать субъективный процент готовности вместо матрицы.

Выход: 100% известных строк инвентаризированы; независимая опись сверена с основной; каждый применимый этап имеет доказательство либо открытый блокер (блокер не закрывает спринт); нет P0/P1 без исправления и независимого воспроизведения, нет непроверенных критичных цепочек, все тесты и регрессии на интегрированном SHA, реальный Unity-прогон/TestChamber/сон/лагерь/личная и автоэкспедиции/загрузка, авторская приёмка. Оставшиеся P2 и намеренно отложенные функции — только с явным решением автора. Если Unity недоступен, спринт остаётся неприёмленным, даже если вся статическая часть зелёная. После выхода реестр и ворота остаются постоянной частью разработки и CI; вновь добавленная функция автоматически открывает строки проверок. Только после приёмки возвращать расширение AOS и Режиссёра памяти.
