## Контракт, который требуется доказать
Roster ID и Soul ID → отправленный участник → проекция развилки → начальная проекция боя → восстановление каждого раунда → исторические actor/target ID → фактический выживший → тот же roster ID → память, отношения, состояние, плата. ID проекции может быть отдельным: нужен явный неизменяемый mapping, а не переиспользование общего mutable хранилища. На исследованном SHA память и эмоции живой AOS по ID не попадают в проекцию (R2-02); свежий патч EmotionSave это не исправляет.

## Приёмка и независимые контроли
- Два воина с разными ID, одинаковым именем в разных моментах кампании. Старший с адресной памятью, активным Fear и семью спектрами. Отдельно заменить roster ID в копии сейва, оставив имя и actor ID. Никаких начислений при неподтверждённой идентичности.
- Развилка, бой, каждый раунд, save/reload/new process, возврат, новый поход. Сверить исходный и проекционный ID, абсолютный/относительный HP, максимальное HP, память/эмоции и фактические голоса. Непрерывный и покадрово восстановленный бой обязаны согласоваться при эквивалентном времени и одинаковом состоянии.
- Два одновременных похода, смерть и рекрут с прежним именем, два слота, уход командира, отзыв, пограничное HP. Проверить раздельно реальный runtime и чистые тесты. Новые нарушения именования не лечить простым копированием глобальных записей в проекции без изоляции.
- Сохранить положительные свойства: запрет одинаковых имён при отправке, уникальность checkpoint actor ID, реальные события и HP в реплее, проверку пересечения поездок по именам (заменить на ID не ослабляя гарантий), отказ от повторного расчёта уже разрешённого боя и изолированный scope стратегии.
- R16 не закрывает старые F03/F04/F07/F21. Не добавлять новых голосов, систем или контента. Игровые исходники не менялись.
