## Арифметическая проверка затухания
Default DecayRate=.01, Joy=.9: t=0 .9; 100s .45; 900s .09; 1700s .05. Vivid требует abs> .05, т.е. около 28m20s запись исчезает из отношений/голосования, даже если хранится до cleanup <=.01. Это игровое масштабированное Time.time; не реальное календарное время. Проверить разные типы, долгий поход, паузу, save/load, лорные 20 лет. Не менять скорость без измерения/авторского решения.

## Положительные находки
MemoryProcessor.Vivid использует abs для отрицательной памяти; сохранение хранит возраст, а не абсолютный Time.time; Bodyguard.GuardForRescue/Absorb проверяет адресную цель, реальный удар и союзность, пишет спасение только после перехвата; CombatManager.TryReportDeath защищает от повтора. Не считать runtime принятым без отрицательных тестов. Связи спасителя/спасённого адресуются ID в OnAllySaved.

## Приёмка
Тесты: 1/5/50 спасений, чередование противоположных событий, достижимость границ отношений из реальных событий, нейтралы-соперники и невидящий свидетель, дружественный/собственный урон, герой после смены сцены/слота, память убитого в банке, эмоции .02/1/0, одинаковые интенсивности, возврат старого сейва, неизменяемый снимок исторического решения, два разных слуха одного героя, провал/ничья/победа с одинаковыми потерями.
