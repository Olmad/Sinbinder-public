# Sinbinder: пять рабочих сессий, новая структура
**Прямое решение автора: 24.11.2026.** Этот регламент заменяет старое распределение «три независимых аудитора» и метод бесконечного перепрохождения всех текстов каждой сессией. Исторические доказательства и планы сохраняются. При конфликте поручений/передачи задач с 00-TEAM-CHARTER.md по ролям действует этот документ, но прежние ограничения безопасности и авторский Stage 1 остаются.

## Результат, а не количество отчётов
Stage 1: завершить полную достоверную проверку **критических** текстов основного цикла: Whisper, SoulCourt и 13 голосов, BattleNarrator, AOS-приказы/последствия, экспедиции/реплей, ключевые диалоги, обучение и Tab/V, связанные RU/EN строки. Нужны факты, исходные контексты, пол, память, игрок/среда, точные переводы и регрессии. После формальной независимой приёмки и отсутствия P0/P1 передать владельцу заключение GO/NO-GO. **Без явного разрешения автора нельзя** начать широкий UX-спринт, новые механики или автоматически снять NO-GO. Полный охват остальных ~582 исходников + изменённых/новых остаётся Stage 2 и не должен бесконечно блокировать переход после авторского решения.

Сохранить все пять существующих ежечасных запусков, не создавать лишних задач.

## Обязательная цепочка передачи
1. DISCOVERED: обнаружено предположение, без объявленного FAIL.
2. CONFIRMED: исходный файл, blob/commit SHA, точный вход и вызывающий путь, наблюдаемое расхождение, позитивный/негативный контрпример.
3. IN_PROGRESS: единственный назначенный №4 владелец. Перед работой найти существующий PR, **не создавать дубликаты**.
4. FIXED_SOURCE: минимальный патч от актуального feature/server-prototype в **изолированной ветке**; DRAFT PR, сохранённый тест на прежнюю ошибку. Никакого переписывания AOS ради текста.
5. CI_PASS или CI_FAIL: выполнить применимые реальные тесты на точном SHA. Отделять source checks, Roslyn, .NET shim и Unity. Невыполненный тест никогда не PASS.
6. QA_ACCEPTED_SOURCE / REJECTED / NEEDS_UNITY: №5 независимо сравнивает diff, проверяет границы и реальные отрицательные случаи; вердикт с SHA и ссылкой в PR. При отказе обратно конкретному владельцу.
7. READY_FOR_INTEGRATION: №4 сравнивает с **актуальной** базой, готовит композицию QA-принятых патчей; сам ничего не вливает.
8. INTEGRATED_SOURCE / CLOSED: только по явному решению автора, с проверкой source blobs и CI после интеграции; CLOSED только если необходимые runtime-проверки пройдены либо обоснованно не требуются.

Статус BLOCKED с указанием конкретной недостающей возможности полезнее фиктивного коммита. Не заявлять работу в Unity и запуск на двух ПК без реальных логов.

## GitHub как точка синхронизации
- Сверять HEAD feature/server-prototype каждый запуск. Main и work-table не трогать, не применять force-push.
- Существующий PR представляет карточку задачи. В описании/комментарии указывать: ID, владелец, статус, контрпример, source SHA, затронутые файлы, тест с ссылкой, вердикт QA №5, Unity, следующее действие. Для новой независимой задачи создавать только одну карточку/PR, не плодить копии.
- Передача №1–3 → №5 после CI; №5 → владелец при REJECTED или → №4 при QA_ACCEPTED_SOURCE; №4 → автор при разрешении/Unity. Одинаковый дефект не обсуждать повторно без нового контрпримера.
- Исторические файлы 88-INDEPENDENT-AUDITOR-1..5-PROGRESS.tsv сохраняют доказательства; не переписывать массово, не менять инвентарь ради искусственного PASS, не отключать строгие правила audit gate.
- На каждом запуске один существенный проверяемый шаг; если исправление невозможно, записать точную блокировку, а не повторить старый отчёт.
