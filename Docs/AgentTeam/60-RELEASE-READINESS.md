## 2. Список конкретных проходов для Unity (заполнять по факту)

Формат отчёта на каждый тест: `SHA | Unity version | ОС/ПК | время | исход PASS/FAIL/BLOCKED | ссылка на лог/видео | воспроизведение | ожидаемое/фактическое`. Не объединять результаты разных SHA в один «всё проверено».

### U1. Первый вход и управление
- [ ] Чистая установка на Windows; старт сцены без ошибок.
- [ ] Tab меняет только tactical/FPS; V только в FPS меняет Командир/Воин **без смены камеры**.
- [ ] Командир ЛКМ выбирает, ПКМ отдаёт приказ; Воин ЛКМ бьёт, ПКМ блокирует.
- [ ] После переключения режима старые назначенные цели, клики и приказ не «доисполняются» в чужом режиме.
- [ ] Подсказки и tooltip не обрезаны на 1366×768 и 1920×1080, русский текст не заслоняет бой.

### U2. Настоящая AOS, а не анимация решения
- [ ] Протокол конкретного воина: `Order revision → 13 voice votes → raw verdict → effective action → world effect → memory/favor → next vote`.
- [ ] Приказ A → отказ → сразу приказ B. До нового голосования нет причины от A под новым приказом.
- [ ] Приказ A → отказ → повторный тик A. Не растут бесконечно обида, эмоции и реплики, повторная пауза не блокирует игру.
- [ ] Отложенное после отказа действие для A не запускается после нового B или отмены.
- [ ] Шёпот Z: соглашение на A не переносится на B; согласие/плата/коррупция соответствуют **реальному** исходу.
- [ ] Принуждённое шёпотом послушание не начисляет заработанную лояльность и не искажает показ 13 голосов.
- [ ] `Idle` после `Move` останавливает прежний путь; `Defend` удерживает пост и атакует только подходящих врагов.
- [ ] Спасение: `GuardForRescue → реальный положительный удар → Absorb → память/деяние`; нулевой/отсутствующий attacker не снимает охрану и не создаёт спасение.
- [ ] Перезагрузка/смена вылазки: память, отношения и личность остаются последовательными; любые сознательные границы сохранений задокументированы.
- [ ] Рассогласование «что проголосовали»/«что реально сделал» видно в диагностике, не скрывается за красивой фразой.

### U3. Сон / первые 15 минут
- [ ] Понятная первая цель на 1-й минуте, понятные последствия Tab/V на 5-й, смысл отказа и исправление на 15-й.
- [ ] Никакое обучение не гарантирует согласие AOS скрытым override.
- [ ] Реальное спасение засчитывается только после фактического перехвата удара.
- [ ] Есть безопасный выход из зависшего шага: повторное решение, смена контекста, корректный restart.
- [ ] Финальный экзамен не выдаёт заранее правильные действия и проверяет обычные игровые системы.

### U4. Реальная сеть
- [ ] `Test-World-Auto.cmd` на Windows: авторская сборка соответствует HEAD; два запущенных клиента, не два shim.
- [ ] Одна Multiplayer_Test карта; два независимых Греховода, их реальные позиции/HP и управление.
- [ ] Авторизованный server order → доставлен Warrior → его **настоящее** AOS-решение → мировое действие. Четыре разных события, не один ACK.
- [ ] Невидимый враг не раскрывает координаты; ошибка snapshot-проекции **снимает** старые данные, успешный следующий кадр восстанавливает нужные.
- [ ] Disconnect/reconnect, новая/старая команда, death/despawn и повторный матч не создают ghost actor/незаконных приказов.
- [ ] Любой сетевой публичный доступ и пароли не использовать до защищённого транспорта; localhost/LAN не равны безопасной интернет-комнате.

### U5. Долговечность и производительность
- [ ] Сохранить → выйти → запустить → загрузить: команда/состав/лояльность/карман/души/память проверены раздельно.
- [ ] 10/30/100 воинов: записать FPS, CPU/GPU, GC allocations, AOS tick cost, NavMesh, максимальный кадр, память.
- [ ] 30–60 минут с боем, сменой роли и сценой: нет утечки объектов/событий, повторного лута, саморазмножения памяти/деяний.

## 3. Как вносить результаты пяти сессиям

1. Перед запуском прочитать актуальный HEAD, [issue #3](https://github.com/Olmad/Sinbinder-public/issues/3) и применимые пункты настоящего файла.
2. За запуск закрывать один доказуемый дефект либо одну проверку: дать `before/after`, SHA, указать проверенные G0–G7.
3. Привязывать доказательства к **одному** коммиту. Если HEAD после теста сменился, CI предыдущего коммита остаётся историей, не автоматическим PASS для нового.
4. QA имеет право помечать gate `BLOCKED`, не объявляя всю игру неиграбельной без runtime-доказательства.
5. При межсессионной передаче фиксировать владельца, конкретный воспроизводимый сценарий, критерий завершения и ссылку на journal. «Передано» != «исправлено».
6. Не создавать новые большие системы до закрытия G3 и качественной проверки G4; сетевые функции с риском регрессии остаются изолированными и тестируемыми.
