# Sinbinder: изоляция автоматического AOS и история души

**Дата:** 12.11.2026  
**Ветка:** `feature/server-prototype`  
**PR:** №1 (draft, `main` не менять)  
**Проверка:** GitHub Actions и реальные .NET API shim. **Unity PlayMode и LAN host/client не выполнялись.**

## 1. Изолирована стратегия отряда

**Обнаруженная ошибка.** `AutoBattleResolver.Session.StepRound` временно вызывал `Gameplay.SquadOrders.Set(_strategy)` и после хода `Set(previousOrders)`. `Set` запускает событие `Changed`, предназначенное для **настоящего изменения стратегии игроком**. В двух одновременных удалённых экспедициях UI и остальные слушатели могли получать лишние переключения на стратегии невидимых отрядов и обратно каждый ход.

**Исправление:**
- `Gameplay.SquadOrders.UseForSimulation(strategy)` создаёт вложенную область временной стратегии на время вычисления голоса. `CurrentModifiers()` читает её, если задана, а не публичную настройку игрока.
- `Current` и `Changed` больше не трогаются фоновым AOS; `Set` и `Reset` для настоящего управления остаются без изменений.
- `AutoBattleResolver.Session.StepRound` выполняется в `using`-области: сбои возвращают прежнюю область без лишних уведомлений.
- Нормальные UI-команды и прочая тактическая логика не менялись.

**Тесты:** реальный `StrategyDatabase` и все 13 модулей подтверждают штрафы/бонусы внутри области, отсутствие `Changed`, вложенные области двух отрядов и восстановление после исключения. Дополнительно реально выполняются два параллельных боя с разными командирами.

## 2. Не терять нарративные перки при создании временного воина

**Обнаруженная ошибка.** В `SquadRoster.Member` хранится `Core.MemorySeed Seed`, включающий историю и `NarrativePerks`. Но `Expedition.Summon` создавал `SoulData` с `memory: null`. Поэтому краткоживущая копия бойца для советов командира и автоматического AOS теряла историю, хотя настоящий воин в склепе её имел.

**Исправление:** `Expedition.Summon` передаёт `m.Seed` через `Make(..., MemorySeed memory = null)` в штатный конструктор `SoulData(..., memory, ...)`. Копия, созданная после восстановления боя, снова получает тот же `Seed` из исходного `SquadRoster.Member`.

- Не создаются новые перки, события памяти, души или игровые состояния.
- Вопросы статуса персонажа по-прежнему решаются оригинальными модулями AOS.
- Если `Member.Seed` пуст по данным исходного ростера, искусственная память не создаётся.
- Исправление само по себе **не доказывает**, что все эффекты перков включены и корректно настроены в реальной `PerkDatabase`.

**Тесты:** `AosSessionChecks` и `BoardRealAosChecks` проверяют передачу существующей истории по ссылке при первичном вызове `Summon` и после сохранения/загрузки боевого хода.

## 3. Удалённая местность не равна текущей сцене игрока

**Обнаруженная ошибка.** `PerkResolver` использует `Core.LocationManager.HasTag(tag)` для условий `InCrypt`, `InRuins`, `NearWater`, `InForest` и других. `LocationManager` по умолчанию описывает **загруженную сцену игрока**, а не место удалённой автоматической экспедиции. Получив историю/перки, временные AOS-воины могли ошибочно получить эффекты `Crypt`, даже находясь на миссии в другом месте.

**Исправление:**
- `LocationManager.ForOffscreenSite(params string[] knownTags)` изолирует проверку местности и не меняет `CurrentLocation`. Поддерживает вложенность и освобождается через `IDisposable`.
- `Expedition.CombatEncounter.StepRound` входит в эту область ровно на время **исполнения настоящего AOS-хода**.
- Пока `MissionCatalog` не содержит подтверждённых тегов местности, вызывается пустой список: **не придумывать**, что «часовня» точно `Ruins`, а «каменоломня» точно `Cave` или `NearWater`. Отсутствие бонуса лучше ложного бонуса от чужой сцены.
- Реальная сцена и личная экспедиция не затронуты.

**Тесты:** компилируется настоящий `Core.LocationManager.cs` в комбинированном стенде, где сцена игрока помечена `Crypt`. Проверяется отсутствие этого тега в фоновой области, явный `Cave` для вложенной области, возврат `Crypt` после исключения и после реального хода AOS. Наблюдатель точки вызова `PerkResolver` проверяет, что настоящие вызовы AOS выполняются без чужого тега. Полный production `PerkResolver` пока подменён в shim, поэтому его эффекты должны быть протестированы следующим этапом.

**Важное ограничение:** override рассчитан на синхронное исполнение Unity игрового цикла. Если будущий сервер будет распараллеливать AOS по потокам, понадобится thread-local либо явно передаваемый объект контекста, а не единая статическая область.

## 4. API-shim / CI

Проверки запускаются постоянно из `.github/workflows/expedition-integrity.yml`, включая:
- `Tools/expeditions/AosSessionChecks.csproj` (48 независимых проверок production пошагового боя);
- `Tools/expeditions/BoardShimChecks.csproj` (32 проверки жизненного цикла `MissionBoard`);
- `Tools/expeditions/RealAosShimChecks.csproj` (10 проверок оригинального `BehaviourResolver` и 13 модулей);
- `Tools/expeditions/BoardRealAosChecks.csproj` (**51 объединённая проверка** настоящего `MissionBoard`, 13 модулей, стратегий, истории души и местности).

В обоих сценариях запускаются сохранение после одного хода, восстановление, продолжение боя, мирная развилка командира и отложенный возврат. В комбинированном .NET проекте подавлено только предупреждение `CS0649` для инспекторского `[SerializeField]` поля из реального `LocationManager`; исходная игровая сериализация не изменена.

Workflow теперь реагирует на изменения `AOS Engine/**`, `Gameplay/SquadOrders.cs`, `Core/LocationManager.cs`, `Core/MemorySeed.cs` и `Core/Soul/**`. Иначе корректировки личности могли незаметно обходить тесты экспедиций.

## 5. Приёмка Unity и открытые риски

1. В Unity вручную выставить игроку `Defensive`, одновременно пустить два автоматических боя командиров с Гневом и Жадностью. Ни панель тактики, ни `SquadOrders.Changed` не должны переключаться; реальное голосование должно получать свои модификаторы.
2. В автопоход отправить воина с `MemorySeed` и настоящим перком из базы; убедиться, что доступные `Always` и авторизованные контекстом события влияют на голос, а память сохраняется после загрузки.
3. Находясь в сцене склепа с тегом `Crypt`, запустить автоматический бой на другой карте: никакой перк `InCrypt` у удалённого отряда не должен сработать. При настоящем бое в склепе перк должен по-прежнему работать.
4. Добавлять реальные теги территории только после появления утверждённого источника данных для каждой миссии/уровня. Сейчас не выдавать игроку фальшивые бонусы от местности.
5. Проверить другие скрытые внешние зависимости AOS: `EmotionSystem`, `PerkResolver`, `TemptationResolver`, `MemoryProcessor`, `AOSStats`, их сохранение/побочные эффекты, а также серверный авторитет и Unity `JsonUtility`.
6. Проверить Unity Console, F5/F9, последовательность ходов, бегство, гибель, реальную выдачу монет/оболочек, ограничения на души и секреты, Tab/V и личные карты.

**Итог:** реальные ошибки передачи стратегий, биографии и местности исправлены; API shim не заменяет настоящие физические сцены, ресурсы и сетевой запуск.
