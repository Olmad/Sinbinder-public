# Sinbinder — настоящий Суд последнего решения по J (не shim)

> **Обновление 16.11.2026 — клавиша изменена.** Этот файл сохраняет **историческое** описание первоначальной реализации по `J/Shift+J`. На текущем production-коде после коммита [`8f059473`](https://github.com/Olmad/Sinbinder-public/commit/8f0594734764987fa99ea0aed882c03e95636c12) Суд вызывается **U / Shift+U**, потому что `J` уже переключает банки (`SatchelHands`). Во всех проверках ниже читать `J` как `U`, `Shift+J` как `Shift+U`; менять старую историю этого документа не нужно. См. [аудит 17.11](84-FULL-TEAM-AND-PROGRESS-AUDIT-2026-11-17.md).

**Дата:** 2026-11-15. **Ветка:** `feature/server-prototype`. **PR №1:** DRAFT, не сливать до Unity PlayMode. **Статус:** production Unity C# изменён; настоящая сборка Unity Editor и игровая приёмка не проводились.

## Что изменилось в игре

- **J**: если выбран **ровно один живой союзный воин**, у которого AOS уже приняла решение **по приказу**, открыть существующий кинематографический `SoulCourt` с его последним решением. **Shift+J** открывает полный, а обычный J — короткий суд.
- Кнопка встроена в **реальный** `SelectionManager.Update`. После обнаружения корректного снимка используется существующая игровая корутина `SoulCourt.Convene`, камера, пауза, визуальные судьи, весы и возврат управления. Не добавлены вторая имитация суда или демонстрационная сцена.
- В `SelectedUnitPanelUI` при наличии записанного решения видна подсказка **J — Суд решения**.
- Если никого не выбрали, выбрали нескольких, решение ещё не записано, настройка суда отключена, либо в сцене нет кино-камеры/Letterbox, игрок получает конкретное объяснение через `BattleLogUI` (если он присутствует). Во сне системный суд не перехватывается.
- **Честное ограничение первой версии:** текущий `SoulCourt` голосует **за/против приказа**, поэтому J на последнее самостоятельное решение **без приказа** не показывает ложный «приказ исполнен», а объясняет, почему этот тип суда пока недоступен. Поддержка самостоятельных поступков — отдельная игровая переработка зала суда.

## Почему при повторном просмотре голоса настоящие

- В production `BehaviourResolver.DecideDetailed(w,c,List<Vote>)` добавлен необязательный witness: при **том же** `Tally`, который выбирает действие, записывается вклад всех 13 исходных модулей AOS. Существующий `DecideDetailed(w,c)` не меняет поведение.
- `AOSWarriorWrapper` сохраняет `LastDecisionBallot`, `LastDecisionOrderKind` и копию `LastContext` (с отдельной копией списка воспоминаний) **после** настоящего решения. Для вражеских NPC лишний массив не создаётся.
- `SoulCourt.Convene` принимает optional `originalVotes` и передаёт их `Seat`. При наличии originalVotes не пересчитывает прошлые голоса через `BehaviourResolver.Ballot(w,c)` и не заново вычисляет ранее отсутствующий контрфактический фактор `Weigh` по текущему изменённому состоянию персонажа.
- Сценарий **«две воли»** уже работает на уровне презентации: если `LastWhisperCompelled`, в суд передаётся `NaturalDecisionDetail` (выбор до Шёпота), а отдельная реплика объясняет, что фактическое подчинение было результатом вмешательства Греховода.
- Голоса 13 модулей — **не весь итоговый счёт**. Дополнительно влияют вещи, нарративные перки, установка отряда и специальные вмешательства. Суд прямо оговаривает эту границу; будущая итерация должна записывать и показывать итоговые `actionScores` и разбивку дополнительных модификаторов, чтобы убрать разрыв между весами и конечным выбором.

## Изменённые production-скрипты

1. `Assets/Scripts/AOS Engine/BehaviorResolver.cs` — захват голосов из действительного счёта.
2. `Assets/Scripts/AOS Engine/AOSWarriorWrapper.cs` — сохранение последнего бюллетеня, контекста и приказа.
3. `Assets/Scripts/Gameplay/SoulCourt.cs` — исторические голоса и Шёпот в настоящем 3D суде.
4. `Assets/Scripts/Gameplay/SelectionManager.cs` — реальная команда J/Shift+J и игровые ограничения.
5. `Assets/Scripts/UI/SelectedUnitPanelUI.cs` — контекстная подсказка в уже существующей панели.

**Регрессионная страховка:** `Tools/expeditions/RealAosShimProgram.cs` компилирует реальный `BehaviourResolver` и настоящие 13 модулей, проверяет идентичность записанного бюллетеня бюллетеню исходного голосования, сохранение валидного действия и неизменность старых голосов при смене HP/опасности. Это **не** физическое Unity PlayMode, а проверка логики источника данных.

## Обязательная Unity-проверка перед merge

1. В тактическом виде Tab выбрать одного союзника, отдать приказ X (отход), дождаться решения AOS. Под панелью персонажа появляется J. Нажать J, убедиться, что сцена суда реально открывается, 13 судей, весы, затем **пауза и камера корректно возвращаются**. Никаких новых приказов или очков репутации от просмотра.
2. Нажать Shift+J, проверить полный суд, отсутствие ошибок Console и возможность вернуться в прежний вид с прежним состоянием выделения.
3. Проверить уникальную причину и голоса при двух разных воинах. Если нет отличия в решении, объяснение не должно его выдумывать.
4. Успешный Шёпот при собственном неповиновении: J показывает **самостоятельный** отказ и **фактическое** принуждение отдельными фразами; память доверия не начисляется повторно.
5. После реального голосования изменить HP/снаряжение/ситуацию до следующего решения, открыть J; старый бюллетень не должен пересчитываться. Если уже принято новое решение, J должен показать именно **последнее**.
6. Без приказа, без выбранного воина, с двумя выбранными, с мёртвым бойцом, в модальном окне, на паузе, на сцене без кино-ригга и при выключенном суде: ни ложной сцены, ни команды, ни подвисшего курсора.
7. Сон-туториал и сюжетный суд должны оставаться работоспособными с прежним `SoulCourt.Convene` без опциональных параметров. Tab/V, бой, Follow/Selection, LAN Host/Client, режим Warrior проверяются на регрессии.
8. Проверить нагрузку: у 10–25 активных союзных бойцов создаётся новый небольшой список голосов каждый тик решения; при необходимости снизить выделения GC без изменения данных суда.

**Статус проверок:** на кодовом коммите `39981f27af49524882997294b5028aaf1067a817` 7 GitHub Actions завершились `success`, включая настоящие 13 модулей AOS. После последней доработки проверки доступности сцен нужна отдельная CI-проверка. **Unity PlayMode не подтверждён.**

## Следующие игровые шаги

1. Суд самостоятельного поступка без приказа: два сравниваемых **действия**, а не фиктивные стороны «за приказ/против».
2. Записывать итоговые счета действий плюс внешние поправки, чтобы и при перках/стратегии весы отображали реальную причину решения, а не только голоса личности.
3. «Что, если?..»: эксперимент по одному фактору из **замороженного снимка** с вычислением без побочных эффектов, никаких фальшивых исходов боя.
4. Опциональный короткий UI просмотра решения без принудительной длинной кинематографической сцены.
