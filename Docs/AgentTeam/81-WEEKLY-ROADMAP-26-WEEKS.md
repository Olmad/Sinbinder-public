## A. Контракт каждой недели

- **Одна фраза результата для игрока.** Не «улучшаем UX», а «игрок после Суда может повторить тот же приказ, увидеть новое решение, понять причину».
- **Максимум три обязательные подзадачи:** (1) воспроизвести/измерить baseline; (2) исправить или реализовать выбранный минимальный production slice; (3) проверить в Unity и зафиксировать before/after. Задачи резервной инфраструктуры не заменяют основной результат.
- **Один владелец темы + QA на приёмке;** другие роли работают как поддержка, берут ровно один новый воспроизводимый риск либо согласованный безопасный подпункт. Не нужно заставлять все пять сессий коммитить каждый час.
- **Запрет ложного DONE:** .NET shim → подтверждает только конкретный source/test; Discord/GitHub comment → только сообщение; Unity Play Mode с SHA + видео/лог → доказательство поведения. Произвольные тестовые кнопки и автотелепорты не доказывают понятность игроку.
- **Если к воскресенью нет приёмки:** статус `PARTIAL/BLOCKED/FAILED`; оставить артефакт и причинный блокер, следующий понедельник **повторить/сузить** именно незакрытый результат. Нельзя закрыть неделю только потому, что наступила следующая.
- **Любой подтверждённый P0** временно замещает тему: устранить, повторить G3/G4; после этого вернуться к незакрытой неделе. Случайный P2 не забирает текущую неделю.
- **Игра уже играбельна.** Оценивать полировку, объяснимость и законченный цикл, не писать, что игра впервые становится «проходимой».
- **SOLO FIRST:** мультплеерная сессия в эти недели занимается только изолированными тестами безопасности и не трогает общий gameplay/сцены без согласованного P0. Полноценная общая карта — отдельный NET-G после R0.
- **Планирование vs выполнение:** график W01–W26 — стартовая гипотеза. В каждой недельной карточке обновлять фактические даты и `DONE/UNKNOWN`; не переносить проценты без доказательств.
- **Сохранность:** только `feature/server-prototype`, `main` и `work-table` не трогать, PR №1 draft, без force push, никаких фиктивных CI/Unity.

## D. Кто делает что в рамках ОДНОЙ цели

| Роль | Содержание полезной работы только внутри текущей недели | Приёмка |
|---|---|---|
| **Логика** | Контрпример AOS/памяти/урона/причин, минимальный fix + тест, только относящийся к недельной цели | Зафиксированный реальный исход, не подмена решением сценариста |
| **UX/обучение** | Один узкий провал действия/объяснения/управления, понятные игровые надписи, замер 1/5/15 мин | Наблюдаемая понятность и отсутствие ложного статуса |
| **Визуал** | Художественный элемент выбранной сцены/события, реальные модели/свет/анимации/VFX, один screenshot before/after | Автор видит изменение в кадре и не потеряны GUID/производительность |
| **QA/интеграция** | Контроль одного HEAD, CI, Unity чек-листа, before/after, регрессии соседних систем; реальные логи | QA evidence и приёмка пользователя для G3+ |
| **Мультиплеер** | Безопасность и неразрушающая тестовая поддержка сети, если относится к неделе; иначе регрессии, не новые сервисы | Изолированная проверка, отсутствие регрессий соло |
| **Автор + текущая неавтоматическая сессия** | Выбор и заморозка объёма, личный Unity прогон, слияние наблюдений, исправления самых ценных рисков, решение о DONE | Чёткий ответ «работает/не работает/не проверил» со ссылкой на SHA |

**Правило против имитации деятельности:** короткий, честный отказ от ненужной правки лучше, чем пустой docs-коммит или десятый одинаковый «нужен Unity». Первая подходящая задача должна закончиться либо тестом/изменением, либо новым конкретным blocker. Почасовое расписание само по себе не гарантирует продуктивных 40 минут.
