# Sinbinder: облачная проверка Unity без локального редактора

**Дата:** 11.11.2026. **Ветка:** `feature/server-prototype`. **Статус:** облачный workflow создан, выполнение настоящего Unity Editor зависит от лицензии. Это НЕ релизное разрешение.

## Что реализовано

- `.github/workflows/unity-cloud-smoke.yml`: дешёвый preflight без лицензии (версия 6000.3.22f1, manifest Test Framework, существование сцен и .meta).
- Настоящий Unity Editor smoke **выключен по умолчанию** и включается только repository variable `SINBINDER_UNITY_CI_ENABLED=true`. Он использует `game-ci/unity-test-runner@v4` на Ubuntu, `EditMode`, без coverage, сохраняет результаты в artifact.
- `Assets/Tests/Editor/CloudProjectSmokeTests.cs` + `.asmdef`: Unity NUnit проверяет редактор, импорт важных сцен через AssetDatabase и сцены Build Settings. Тесты не создают/не сохраняют сцены.
- Нет PlayMode, Windows Player, кадров на экране, игры двух клиентов или UX-теста. Успешный preflight = L0, успешный реальный EditMode import + compile = часть L3, но **НЕ L4–L7**.

## Как активировать Unity job

1. Проверить лицензионную возможность. У Unity Personal ручная активация через прежний веб-ALF сервис более не гарантируется; GameCI v4 описывает получение `.ulf` через Unity Hub. Если Unity Hub недоступен, этот путь может быть пока заблокирован. Не обходить лицензирование.
2. В **Settings → Secrets and variables → Actions** репозитория создать секреты:
   - Personal: `UNITY_LICENSE` (содержимое законно полученного `.ulf`), `UNITY_EMAIL`, `UNITY_PASSWORD`.
   - Pro: `UNITY_SERIAL`, `UNITY_EMAIL`, `UNITY_PASSWORD` (не требуется `UNITY_LICENSE`).
   Никогда не помещать значения в код, issue, PR, комментарии или CI logs.
3. Создать **variable** `SINBINDER_UNITY_CI_ENABLED` со значением `true` **только после настройки лицензии и проверки лимитов Actions**.
4. Сделать новый коммит по файлу самого workflow или `Assets/Tests/Editor/**` в `feature/server-prototype` для запуска. `workflow_dispatch` предусмотрен, но GitHub UI может не показывать новую ручную workflow до появления файла в default branch. В `main` ради запуска НЕ мержить.
5. Смотреть job `editor-import` и artifacts; зафиксировать SHA, Unity Editor version, тесты и ошибки. При сбое импорта/лицензии не выдавать результат за PASS.
6. Снять variable (или поставить `false`), если облачный Unity больше не нужен. CI сделан узкосрабатывающим, чтобы ежечасные пуши остальных сессий не запускали тяжёлые контейнеры.

Документация GameCI: https://game.ci/docs/github/test-runner/ и https://game.ci/docs/github/activation/

## Что остаётся для закрытия релизных ворот

- **G3 / L3:** реальный Editor import + compile на актуальном SHA, без compile errors и Missing Script, отдельная проверка критических сцен (NUnit smoke не доказывает отсутствие Missing Script внутри объектов).
- **G4 / L4:** соло Play Mode: Tab/V, 13-голосное решение AOS, отказ, шёпот, последствия, сон, бой, смерть, сейв.
- **G5 / L5:** host + 2 реальных Unity Player. Это отдельная проверка; её нельзя заменять TCP shim.
- **G6 / L6:** плейтест незнакомого человека, когда он станет доступен. Автоматизация не измерит понятность игры.
- **G7 / L7:** чистая Windows-сборка на другом ПК, длительная проверка и решение владельца о выпуске.

## Первый публичный релиз: одиночная демоверсия

Полноценный мультиплеер НЕ является обязательным условием публикации **одиночной** демоверсии. Он не должен затрагивать соло, а экспериментальные TCP-механики сохраняют изоляцию. Нужны: компиляция; непрерывный соло-проход; проверенное Tab/V; понятная демонстрация AOS; корректные сохранения; отсутствие P0/P1; Windows Player; краткие инструкции. При отсутствии Unity и человека остаются статические и production-linked проверки, конкретные отчёты UNKNOWN и устранение доказанных дефектов. Цифры готовности не повышать за счёт количества коммитов.

**Правило для пяти сессий:** сначала текущий HEAD + CI; одно доказуемое изменение/тест в своей зоне; G0–G7 фиксировать честно; не трогать `main`/`work-table`, не сливать draft PR №1.
