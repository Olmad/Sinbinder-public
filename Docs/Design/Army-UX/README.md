## Общая архитектура
Один обзор армии из лагеря/склепа, возможный вход из выбранного воина без добавления конфликтующей клавиши до согласования. Во время боя не перекрывать основной HUD и не менять правила времени. Верхние разделы: Воины, Отряды, Запасы, Души, Улучшения. Воины: постоянный список слева с поиском и фильтром доступности; справа выбранный воин с вкладками Обзор / Отношения / Снаряжение / История / Навыки. Верхняя сводка только фактические внешние ресурсы и численность; никаких средних показателей души, рейтинга эффективности и процента сыгранности. Скрытые характеристики не показывать при сортировке/фильтрации. Отсутствующих можно осматривать по последнему известному состоянию (не «живой» прогноз); запрещённые действия объясняются словами. Вкладка отношений по §14: Б по умолчанию, небольшая кнопка В. Не показывать все 210 возможных отношений сразу.

## Сравнение
A. Единый обзор с контекстными вкладками (макет): легче искать и сопоставлять, один список и общая карточка; риск перегруженности, большой объём UI-работ. B. Раздельные текущие окна с общим навигатором: дешевле, сохраняет атмосферу, но повторный поиск воина и переходы мешают большим составам. C. Только физический осмотр лагеря: сильнее погружение, но непрактично для 15+ воинов и отсутствующих. Рекомендация: A для наблюдения и навигации, B/C для реального действия. Не делать центральное окно всемогущим диспетчером.

## Порядок реализации и доказательства
1. Инвентарь данных и текущих модальных окон/горячих клавиш, стабильный read-only snapshot roster + active journeys, различение live/last known; адаптер без копии игровой логики и записи в состояние.
2. Список и обзор выбранного воина, поиск/фильтры, 3/6/15+ участников, отсутствующий/мертвый/неизвестный, длинные имена, 720p/1080p; возврат в игру с прежним выбором и камерой. Один источник паузы и фокуса; не конфликтовать с I/F/Tab/V/U/Esc.
3. Снаряжение, запасы, души, улучшения как чтение и маршрутизация в уже работающие действия. Проверить запрет дистанционного обмена, отказ, занятость, повтор клика, одну транзакцию, сохранение. Не выдавать результат до действия.
4. Отряды и история: активный поход и реплей читаются из MissionBoard/ExpeditionReplayArchive; не вызывать их повторно. Отношения только после проверенной модели известного знания и исправления ID/памяти. Навыки отображать по действующей реализации.
5. Автор выбирает расположение, вход и названия; затем Unity-прототип и поэтапная миграция. Отдельно визуальная и пользовательская приёмка. Э1 остаётся текущей вехой, UI не заменяет исправление AOS.

Приёмка: любой раздел можно открыть/закрыть без потери ввода, состояния и данных; изменения предметов, оплаты, лечения, связывания и установки проходят только существующие правила; ушедший воин отображается с честным временем знания, скрытые отношения не видны ни в фильтре, ни графе; нет фиктивных навыков, улучшений или заданий. Профиль большого состава и UI, RU/EN, клавиатура и прокрутка. До прогона Unity — проект, не реализация.
