# WorldForge — размещение групп объектов по линиям и равным интервалам

**Ветка:** `feature/worldforge-layout-tools-2026-11-19`.  
**Основа:** `feature/worldforge-best-improvements-2026-11-19`, HEAD `8a8a30c8e24e8472c59892d925c7ef38e27d4a80`.

## Отдельный рабочий участок

Разработчик локального Codex отдельно работает над **числовыми полями инспектора (применение после подтверждения, одна операция Undo)** и **возвратом из пробного запуска к редактируемой карте**. Здесь НЕТ этих двух функций, НЕТ изменений их будущих API. Эта ветка вносит только инструменты расположения уже выбранных обычных props и не меняет структуру JSON.

## Реализовано

В режиме **«Выделить»** выделить 2+ моделей (Shift+ЛКМ, рамка или Ctrl+A). В правом групповом инспекторе добавить новые действия:

| Команда | Поведение |
|---|---|
| X: мин | Выравнивает все X координаты по самой левой точке выделения |
| X: центр | Выравнивает все X по середине между крайними выбранными X |
| X: макс | Выравнивает X по самой правой точке |
| Z: мин | Выравнивает Z по минимальному Z |
| Z: центр | Выравнивает Z по середине между крайними Z |
| Z: макс | Выравнивает Z по максимальному Z |
| Равные интервалы по X | Для 3+ props сортирует по X и ставит на одинаковом расстоянии между исходными крайними X |
| Равные интервалы по Z | Аналогично для Z |

Выполняется **один Undo/Redo для всей группы** и один redraw. При попытке сделать бессмысленное действие (уже ровно, только два props для интервалов, недопустимые координаты) изменения и запись в Undo не создаются. Сохраняются другие координаты, поворот, масштаб, материалы, ID, триггеры и склепы. Для одинаковых X/Z порядок разрешается стабильно по порядку исходных props, без случайного разброса.

## Технические границы

Алгоритм вынесен в `Assets/Scripts/Gameplay/MapObjectArrange.cs` и **не мутирует карту**: `TryPlan` возвращает новый проверенный массив позиций или false. Контроль NaN, infinity, выхода за границу карты и неизвестного режима. Только после успешного расчёта `MapEditor.ArrangeSelectedThings` коммитит позиции через существующий `Change()`. Никакие модификации `MapData.Thing` и JSON-схемы не требуются. У класса есть собственная `.meta` с постоянным GUID.

Тест: `Tools/map-editor/Program.cs:LayoutPlannerContracts` компилирует реальный C# planner и редактор с Unity API shims, проверяет независимость расчёта, сортировку при равных исходных координатах, Undo/Redo, сохранность триггеров/склепов и отказ от невалидного ввода. Статический wiring-тест проверяет наличие команд, вызов planner и Unity .meta. **CI source/stub не является Unity PlayMode.**

## Проверка в настоящем Unity

Выделить три объекта с X 3, 9 и 30, нажать «Равные интервалы по X», увидеть X 3, 16.5 и 30; Ctrl+Z должен вернуть 3, 9 и 30, Ctrl+Y повторить. Затем выделить разные объекты и выровнять по Z: измениться должны только Z. Проверить старый файл карты через Save/Load и работу триггера F на одном из объектов. Редактор с подтверждённым исправлением чёрного экрана не должен потерять видимость.

## Не сделано в этой ветке

Числовые поля с подтверждением и возврат к редактируемой карте из пробного запуска: **приоритет локального Codex**. Свободные 3D-gizmos, шаблоны построек, произвольные скрипты и автоматический запуск Unity сюда не входят.
