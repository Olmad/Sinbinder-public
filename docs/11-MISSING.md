# Чего не хватает

## Реестр недостающего кода

`03-STATUS.md` перечисляет, что написано. Здесь — что не написано или
не подключено, с ценой в вечерах и с указанием, чем именно это является:
**проводом** (код есть, вызова нет), **новым кодом** (класса нет вовсе)
или **не кодом** (сцена, ассет, контент).

Вечер ≈ 2–3 часа.

---

## Коротко

| Категория | Вечеров |
|---|---|
| Провода — чтобы игра стала игрой | 4 |
| Новый код — чтобы игра стала Sinbinder'ом | 8 |
| Показ — чтобы игрок это увидел | 5 |
| Пол — чтобы было во что играть до понимания характеров | 12 |
| **Итого до играбельного демо-ядра** | **~29** |

Двадцать девять вечеров ≈ пятнадцать недель при трёх вечерах в неделю.
Плюс сцены, арт и звук, которые вечерами не считаются.

**Хорошая новость в пропорции: провода дешевле нового кода, а нового
кода нужно меньше, чем кажется.** Четыре вечера отделяют проект от
состояния, в котором главная механика вообще существует.

## 1. Провода — 4 вечера

Код написан и работает. Не хватает вызовов.

### 1.1 Цепочка приказа · 2 вечера · **без этого игры нет**

Разорвана в трёх местах, все три подтверждены чтением.

**Разрыв 1.** `SelectionManager.HandleCommandInput` шлёт приказ мимо AOS:

```csharp
mover.CommandAttack(enemyUnit.gameObject);   // прямо в NavMeshAgent
mover.CommandMove(hit.point);                // голосование не спрашивают
```

Надо: записать приказ на воина, а исполнение оставить голосованию.
Требует нового поля — см. 2.1.

**Разрыв 2.** `AOSWarriorWrapper.Decide()`, строка 31:

```csharp
var context = CombatDecisionContext.Create(_warrior);   // второй аргумент не передан
```

`Create` принимает `commandType`, но его никто не передаёт. Значит
`HasCommand` всегда `false`, значит `LoyaltyModule` всегда возвращает 0,
значит `ObeyCommand` не может победить ни при каких условиях.
**Модуль верности сегодня — мёртвый код.**

**Разрыв 3.** `AOSWarriorWrapper.Execute()` не умеет исполнять
`ObeyCommand`: ветки в `switch` нет, попадает в `default` →
`TryExecuteSkill` → ни один компонент умений не подходит →
`Execute(ActionType.Idle)`. То есть подчинение исполняется как «стоять».

### 1.2 Перки · 1 вечер · **самая дешёвая победа в проекте**

`PerkResolver.ApplyPerks(scores, warrior, context, database)` не
вызывается ниоткуда. За ним стоит сто нарративных перков (77 КБ контента),
не влияющих на игру ни одним битом.

Нужно: поле `PerkDatabase` в `BehaviourResolver` и одна строка
в `DecideDetailed` рядом с вызовом `TemptationResolver.Apply`.
Плюс ассет базы — см. раздел 5.

### 1.3 Отказ как событие · 0.5 вечера

`Decision.RefusedCommand` считается, но никто его не читает.
Нужен вызов `AOSEventHub` и запись воспоминания: воин должен помнить,
что ослушался, а командир — что его ослушались.

### 1.4 Слова решения · 0.5 вечера

`PhraseGenerator` написан, вызова нет. Ему нужны потребители —
это раздел 3.

### 1.5 Остальные мёртвые системы · вне демо

`AutoBattleResolver`, `MissionResolver` + `Quest` + `FalseGodQuest`,
`RumourManager`, `CrisisManager`, `LocationManager`. Около 700 строк.
Уровень 2–3, после демо. Каждая — снова провод, а не новый код.

## 2. Новый код — 8 вечеров

Классов не существует.

### 2.1 Приказ как данные · входит в 1.1

```csharp
// Warrior.cs
public struct PendingCommand
{
    public string Type;      // "Attack", "Move", "Defend", "Hold"
    public Vector3 Point;
    public GameObject Target;
    public bool IsSet;
}
public PendingCommand Command;
public void IssueCommand(string type, Vector3 point, GameObject target = null);
public void ClearCommand();
```

Плюс `AOSWarriorWrapper.ExecuteCommand()` — ветка, которая наконец
исполняет то, что велел игрок.

### 2.2 Семь спектров · 3 вечера · **без этого игра не Sinbinder**

Сегодня `SoulData` хранит один грех и одну интенсивность, и **все
восемь модулей читают одно поле `SinIntensity`**. Воин со значением 80
одновременно предельно жаден, гневлив и уныл. Все воины ведут себя
одинаково, отличаясь только громкостью.

```csharp
[SerializeField] private float[] _spectra = new float[7];  // индекс = (int)SinType
public float Get(SinType sin) => _spectra[(int)sin];
public SinType Sin { get { /* максимум по модулю */ } }
```

Дальше в каждом модуле `soul.SinIntensity` заменяется на `soul.Get(...)`
со своим грехом. Механически, но затрагивает ядро, сохранения
и редакторские скрипты.

Не провод. Рефакторинг.

### 2.3 Четыре недостающих модуля · 3 вечера

Написано девять, зарегистрировано восемь. Нет вовсе:
`PrideModule`, `EnvyModule`, `LustModule`, `GluttonyModule`.
Гордыня — самый интересный характер из четырёх: она отказывается
отступать, отказывается отдыхать и отказывается бить в спину.

`PatienceModule` написан, но регистрировать его отдельно не нужно:
терпение — отрицательный полюс гнева и растворится в спектрах.
То же с `VirtueModule`.

### 2.4 Набор кандидатов из умений · 1 вечер

В `BehaviourResolver` словарь `scores` захардкожен на шесть действий:

```csharp
Dictionary<ActionType, float> scores = new()
{ { Attack, 0 }, { SaveAlly, 0 }, { Loot, 0 }, { Flee, 0 }, { Idle, 0 }, { ObeyCommand, 0 } };
```

В `ActionType` шестьдесят два значения. Пятьдесят шесть навыков
(`WrathSkills`, `PatienceSkills`, `LustSkills`, `GluttonySkills`,
`SlothSkills`, `DiligenceSkills`) написаны и недостижимы: голосование
их не рассматривает. Нужно собирать кандидатов из компонентов умений
воина, а не задавать списком.

### 2.5 Цена потери души · 1 вечер

Сегодня смерть воина не стоит ничего. По замыслу качество души
падает со временем с момента смерти. Кода нет.

## 5. Не код, но без этого не запустится

Репозиторий содержит только скрипты. Ни одной сцены, ни одного `.asset`,
ни одной папки `Resources`. Проверить в редакторе в первую очередь:

| Что | Кто требует | Что будет без него |
|---|---|---|
| `Resources/AOSConfig.asset` | `GreedModule` | `_config == null` → модуль возвращает 0 на всё, жадности в игре нет |
| `Resources/Icons/Attack` и остальные | `AOSWarriorWrapper.GetIconForAction` | значков намерения не видно — первая ступень прозрачности молчит |
| `PerkDatabase.asset` | `PerkResolver` | сто перков не подключить |
| `DialogueDatabase.asset` | `DialogueLoader` | все реплики выродятся в `[Имя]: ...` |
| `CrisisDatabase.asset` | `CrisisManager` | кризисов нет |
| `LocationDatabase`, `StrategyDatabase`, `ClassData`, `ShellData`, `SkillData` | соответствующие системы | вне демо |

`GreedModule` уже пишет предупреждение в консоль, если не нашёл конфиг.
Это первое, что стоит увидеть в логе при запуске.

## 6. Порядок

Не переставляется: каждый следующий пункт упирается в предыдущий.

1. **Запустить в редакторе.** Ни одна ступень не подтверждена, пока
   не нажат Play.
2. **Цепочка приказа** (1.1 + 2.1) — 2 вечера. После этого приказ
   может проиграть голосование, и игра становится собой.
3. **Перки** (1.2) — 1 вечер. Сто единиц контента за один вечер.
4. **Показ** (раздел 3) — 5 вечеров. До этого отказ читается как баг.
5. **Семь спектров** (2.2) — 3 вечера. До этого все воины одинаковы.
6. **Четыре модуля** (2.3) — 3 вечера.
7. **Пол** (`08-FLOOR.md`) — 12 вечеров.

Пункты 2–4 — восемь вечеров — дают **гифку отказа**: единственный
маркетинговый актив, который у проекта может появиться раньше всего
остального.
