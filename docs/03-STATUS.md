# 03 — Состояние кода

Аудит 124 файлов на 27 августа 2026. Каждая строка проверена поиском по
исходникам. Это самый важный файл в папке.

## Коротко

Написано много. Подключено мало.

Основной боевой конвейер AOS живёт и работает. Вокруг него — семь готовых
подсистем, которые **никто никогда не вызывает**. Это не «недоделано на 80%»,
это «сделано, но не воткнуто в розетку».

Хорошая новость: воткнуть дешевле, чем написать. Большая часть плана в
`04-ROADMAP.md` — это провода, а не новый код.

## Мёртвое: написано, не вызывается ниоткуда

Проверено поиском вызовов по всем 124 файлам.

| Система | Объём | Последствие |
|---|---|---|
| **`PerkResolver.ApplyPerks`** | ~110 строк + **100 перков** в `PerkDatabaseInitializer` (77 КБ) | Вся система нарративных перков не влияет на решения. «Мать-волчица», «Бывший Охотник», «Певец смерти» существуют как данные и не делают ничего |
| `AutoBattleResolver` | ~140 строк | Автобой не запускается. Вместе с ним мертвы `StrategyDatabase`, `SquadStrategy`, `BattleRecord` |
| `MissionResolver` + `Quest` + `FalseGodQuest` | ~250 строк | Автономные миссии не работают. Первый сюжетный квест написан и недостижим |
| `RumourManager` | ~35 строк | Слухи не расходятся |
| `CrisisManager` ×2 + `CrisisResolver` | ~260 строк | Кризисы не срабатывают. Две конкурирующие реализации |

## Разорванные цепочки

### Цепочка приказа — разорвана в трёх местах

Ключевая механика игры. Сейчас код делает противоположное замыслу:
у игрока абсолютная власть, подчинение как решение не существует.

**Разрыв 1.** Приказ не доходит до AOS.
```csharp
// SelectionManager.HandleCommandInput, ПКМ
mover.CommandAttack(enemyUnit.gameObject);   // прямо в NavMeshAgent
mover.CommandMove(hit.point);                // AOS не спрашивают
```

**Разрыв 2.** `HasCommand` никогда не становится `true`.
```csharp
public static DecisionContext Create(Warrior warrior, string commandType = "")
// AOSWarriorWrapper.cs:31
var context = CombatDecisionContext.Create(_warrior);   // второй аргумент не передан
```
Следствие: `LoyaltyModule` всегда возвращает 0, `ObeyCommand` не может
победить ни при каких условиях. Модуль верности — мёртвый код.

**Разрыв 3.** `Execute()` не умеет исполнять `ObeyCommand` — нет ветки
в `switch`, попадает в `default` и ничего не делает.

### Личность одномерна

Все модули греха читают одно поле `soul.SinIntensity`. `SoulData` хранит
один грех и одну интенсивность. Воин с `SinIntensity = 80` предельно жаден,
гневлив и уныл одновременно.

Диздок обещает семь независимых спектров. Кода под это нет. Практическое
следствие: **все воины ведут себя одинаково**, отличаясь только громкостью.

### Действий 62, голосуют 6

Все навыки грехов и классов (56 значений `ActionType`) не попадают в
голосование. `WrathSkills`, `LustSkills`, `SlothSkills` и остальные
написаны и недостижимы.

## Что было починено 27 августа

16 типов, на которые код ссылался, не существовали ни в одном файле.
Восстановлены по фактическому использованию: `PerkType`, `PerkEffect`,
`NarrativePerk`, `PerkDatabase`, `VoiceModifier`, `DeedType`, `DeedRecord`,
`ReputationData`, `TitleRule`, `StrategyModifier`, `Rumour`, `BattleRecord`,
`BattleEvent`, `MissionAction`, `NPCData`, `OverheadUI`.

Плюс: удалён дубликат `GreedModule` (CS0101); `MissionAction.cs` содержал
метод вне класса — невалидный C#; `MissionDatabase.GetAction` не возвращал
значение на всех путях; `MissionResolver` лез в `protected`-члены `Quest`;
четыре файла Mission-слоя были без namespace; добавлены `DecisionContext.Commander`
и `MemorySeed.NarrativePerks`; три редакторных скрипта обёрнуты в
`#if UNITY_EDITOR` (иначе падает сборка плеера).

Компилятора в этой среде нет — проверка статическая. Все известные
`CS0246 / CS0101 / CS0161 / CS0122` закрыты, ссылок на несуществующие
типы не осталось.

## Честная оценка готовности

Не в процентах — в том, что можно показать.

| Можно ли уже | Ответ |
|---|---|
| Запустить бой, где воины решают сами | Да |
| Увидеть значок намерения над головой | Да |
| Отдать приказ и получить отказ | **Нет** — цепочка разорвана |
| Отличить жадного воина от гневного по поведению | **Нет** — личность одномерна |
| Понять из игры, почему воин так поступил | **Нет** — только `Debug.Log` |
| Проиграть автономную миссию | **Нет** — резолвер не вызывается |
| Потерять воина и почувствовать это | **Нет** — цены нет |

Первые два «нет» — это Уровень 0 в `04-ROADMAP.md`. Пока они не закрыты,
Sinbinder технически работает, но не является Sinbinder'ом.
