# Стенд балансировки

```
dotnet run --project Tools/bench 400000
```

Прогоняет указанное число голосований через **настоящие модули** игры
и печатает распределения: что воины выбирают, чей голос побеждает,
как часто колеблются и — главное — **как часто не выполняют приказ.**

Unity не нужен. Модули принимают `(Soul, DecisionContext, ActionType)`
и сцены не касаются, так что им хватает заглушки `UnityEngine`
в папке `shim` (шестьдесят строк: `Mathf`, `Debug`, атрибуты).

Файлы игры не копируются, а подключены по ссылке в `bench.csproj` —
стенд не может отстать от кода.

## Что он умеет

| Раздел | Зачем |
|---|---|
| Основной прогон | распределения на текущих весах |
| Потолок голоса | как `MaxVoice` меняет картину |
| Установки отряда | работает ли седьмой рычаг игрока |
| Подбор весов | перебор по трём осям с оценкой качества |
| Именованные варианты | сравнение нескольких наборов весов |
| Порог колебания | сколько оцепенения даёт `HesitationShare` |

## Чего он не умеет

**Он не знает, какие положения бывают в настоящем бою.** Распределение
контекстов задано в `MakeContext` по здравому смыслу: сколько врагов
рядом, какое здоровье, как часто есть добыча. Это догадка. Абсолютные
числа зависят от неё, **сравнения между вариантами — почти нет.**

Поэтому стендом стоит выбирать между наборами весов, а проверять
результат — прохождением. Настоящее распределение даст `AOSStats`,
который печатает сводку в конце боя.

## Цель

Отказ примерно в четверти случаев при отданном приказе. Реже — игрок
не заметит главную механику. Чаще — возненавидит её.
